== 구성

`pnu-ws` 브랜치는 `ops-sc`(한국어 보안 모듈)를 기준으로, `main` 의 운영 모듈(01~06, Observability, Performance Tuning, Lightspeed)을 앞에 붙여 하나로 통합한 매뉴얼입니다.
화면 번호는 01~12 이며(보안 시나리오 인트로는 번호 없음), Observability·Performance·Lightspeed(09/10/13)와 보안 모듈(15-00/15/16/17)의 파일명은 원본과 맞추기 위해 그대로 둡니다.

[cols="1,3,1",options="header"]
|===
| 번호 | 페이지 | 소요 시간

| — | 설정 및 개요 (`index.adoc`) | 10분
| 01 | 설치 및 검증 (`01-installation.adoc`) | 10분
| 02 | 애플리케이션 관리 (`02-app-mgmt.adoc`) | 15-20분
| 03 | Ingress 및 로드 밸런싱 (`03-ingress-loadbalancing.adoc`) | 25분
| 04 | 네트워크 보안 (`04-network-security.adoc`) | 10-15분

| 07 | Observability 및 로깅 (`09-observability.adoc`) | 35-40분

목차 노출은 `default-site.yml` / `site.yml` 의 `module_enable_*` 로 결정됩니다.
pnu-ws 에서는 `install, appmgmt, ingress, netsec, debugging, gitops, observability, performance, ols, security, ztwim` 이 `true` 입니다.

== 사전 준비 (한 줄 실행)

bastion 에서 cluster-admin 으로 `oc login` 한 뒤 실행합니다.
Lightspeed 용 *Azure OpenAI API 키*를 `OLS_API_TOKEN` 으로 넘깁니다 (키는 저장소에 넣지 않습니다).

[source,bash]
----
export OLS_API_TOKEN='<Azure OpenAI API 키>'
bash <(curl -sL https://raw.githubusercontent.com/justone0127/OpenShift_Day_Ops_Korean-demo/pnu-ws/setup-scripts/pnu-ws-scripts/setup-pnu-ws.sh)
----

`setup-pnu-ws.sh` 는 저장소를 `$HOME/OpenShift_Day_Ops_Korean-demo` (pnu-ws) 에 clone/갱신한 뒤 다음을 차례로 수행합니다.

. *01~09 준비* — `setup-core-ops.sh gitops`: OpenShift GitOps Operator 가 없으면 설치하고 ArgoCD 준비를 기다립니다.
  이어서 `setup-core-ops.sh lightspeed`: Lightspeed Operator 설치, `azure-api-keys` Secret 생성, `lightspeed-demo/broken-pod` 배포.
. *10~12 준비* — `setup-security-track.sh all`: 보안 실습(RHBK / ZTWIM / RHACS) 환경 배포.
. *매뉴얼 전환* — `switch-showroom-pnu-ws.sh`: Showroom 이 pnu-ws 브랜치를 보도록 바꾸고 재빌드.
. *점검* — `setup-core-ops.sh check`: 01~09 실습 조건 점검.

액션별 실행:

[source,bash]
----
URL=https://raw.githubusercontent.com/justone0127/OpenShift_Day_Ops_Korean-demo/pnu-ws/setup-scripts/pnu-ws-scripts

bash <(curl -sL $URL/setup-pnu-ws.sh) all          # 전체 (기본값)
bash <(curl -sL $URL/setup-pnu-ws.sh) ops          # 01~09 준비 + 매뉴얼 전환 + 점검 (보안 배포는 따로)
bash <(curl -sL $URL/setup-pnu-ws.sh) env          # 실습 환경만 (01~09 + 10~12)
bash <(curl -sL $URL/setup-pnu-ws.sh) showroom     # 매뉴얼만 pnu-ws 로 전환
bash <(curl -sL $URL/setup-pnu-ws.sh) status       # 점검 + 상태 확인
bash <(curl -sL $URL/setup-pnu-ws.sh) cleanup      # 참가자 실습 리소스 정리
bash <(curl -sL $URL/setup-pnu-ws.sh) cleanup-all  # + 보안 트랙 공통 구성요소까지 정리

# 개별 스크립트
bash <(curl -sL $URL/switch-showroom-pnu-ws.sh)            # 매뉴얼 전환 (네임스페이스 자동 탐색)
bash <(curl -sL $URL/switch-showroom-pnu-ws.sh) --status   # 현재 Showroom 설정 확인
bash <(curl -sL $URL/setup-core-ops.sh) check              # 01~09 조건 점검
----

== 매뉴얼 전환 스크립트가 하는 일

`switch-showroom-pnu-ws.sh`

. showroom Deployment 의 `git-cloner`(initContainer) / `content` 컨테이너의
  `GIT_REPO_URL` / `GIT_REPO_REF` 를 이 저장소의 `pnu-ws` 로 바꿉니다.
. `workshop-vars` ConfigMap 이 있으면 `MODULE_ENABLE_*` 를 pnu-ws 구성으로 맞춥니다
  (RHDP 카탈로그에서 01~09 을 끈 채 프로비저닝했더라도, 나중에 `inject-env-vars.sh` 가 다시 돌 때 목차가 바뀌지 않도록).
. pod 를 다시 띄워 clone → Antora 빌드를 다시 수행합니다. 이미 pnu-ws 를 보고 있으면 재시작만 합니다.

포크를 쓴다면 `SHOWROOM_REPO_URL=<포크 주소>` 를 앞에 붙입니다.

== 01~09 진행 시 주의점

* *참가자 1인 1클러스터 기준*입니다. 01~09 모듈은 고정 네임스페이스(`app-management`, `debug-lab` 등)와
  클러스터 범위 리소스(AdminNetworkPolicy)를 쓰므로, 클러스터 하나를 여러 명이 공유하면 서로 충돌합니다.
* *04/05 의 스크립트*는 Showroom 터미널에서 `raw.githubusercontent.com`(rhpds/openshift-days-ops-showroom)을 받아 실행합니다.
  외부 접근이 막힌 환경이면 `setup-core-ops.sh check` 에서 WARN 으로 표시됩니다.
* *06 GitOps* 는 ArgoCD UI 에 "Log in via OpenShift" 로 로그인합니다. admin 이 `cluster-admins` 그룹에 없으면
  UI 에서 Application 이 보이지 않을 수 있습니다 — `check` 가 경고하며, 필요하면
  `oc adm groups add-users cluster-admins admin` 으로 추가합니다.
* *07 Observability* 매뉴얼은 User Workload Monitoring(`enableUserWorkload: true`)이 "이미 적용됨"이라고 안내합니다.
  `setup-pnu-ws.sh` 가 미리 켜 두며(기존 `cluster-monitoring-config` 설정은 유지), 따로 켜려면 `setup-core-ops.sh monitoring` 을 실행합니다.
* *07 Observability* 는 Loki 저장소로 *ODF(NooBaa) S3* (`openshift-storage.noobaa.io`)를 씁니다. ODF 가 없는 클러스터면
  로깅 실습이 진행되지 않으므로 `check` 의 FAIL 을 확인하십시오. 오퍼레이터(Loki/Logging/Tempo/OTel)는 참가자가 매뉴얼에서 직접 설치합니다.
  Alertmanager 이메일 실습은 클러스터 안에 Mailpit 을 띄우므로 외부 메일 서버는 필요 없습니다.
* *08 Performance Tuning* 은 참가자가 매뉴얼에서 VPA Operator 를 직접 설치하고(`performance-demo` 네임스페이스),
  HPA 는 클러스터 기본 메트릭을 씁니다. 진행자가 미리 준비할 것은 없으며 `check` 가 카탈로그의 VPA 를 확인합니다.
* *09 Lightspeed* 의 OLSConfig 는 매뉴얼 속성 `ols_azure_url`(기본 `https://llm-gpt4-lightspeed.openai.azure.com/`)과
  배포 이름 `gpt-4` 를 씁니다. 다른 Azure OpenAI 엔드포인트를 쓰면 `content/antora.yml` 의 `ols_azure_url` 을 바꾸고,
  배포 이름이 다르면 `13-openshift-lightspeed.adoc` 의 `deploymentName` / `models` 를 맞춰 주십시오.
* 01~09 각 모듈 끝의 *정리* 명령을 참가자가 건너뛰었다면 `setup-pnu-ws.sh cleanup` 으로 한꺼번에 지울 수 있습니다.
