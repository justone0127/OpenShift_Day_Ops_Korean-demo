== 구성

`pnu-ws` 브랜치는 `ops-sc`(한국어 보안 트랙)를 기준으로, `main` 의 모듈 01~06 을 앞에 붙인 매뉴얼입니다.

[cols="1,3,1",options="header"]
|===
| 구간 | 페이지 | 소요 시간

| 시작 | 설정 및 개요 (`index.adoc`) | 10분
| 1부 | 01 설치 및 검증 (`01-installation.adoc`) | 10분
| 1부 | 02 애플리케이션 관리 (`02-app-mgmt.adoc`) | 15-20분
| 1부 | 03 Ingress 및 로드 밸런싱 (`03-ingress-loadbalancing.adoc`) | 25분
| 1부 | 04 네트워크 보안 (`04-network-security.adoc`) | 10-15분
| 1부 | 05 디버깅 및 트러블슈팅 (`05-debugging-troubleshooting.adoc`) | 10-15분
| 1부 | 06 OpenShift GitOps (`06-gitops.adoc`) | 10-15분
| 2부 | 인트로 — RedPay 침해사고 (`15-00-security-story.adoc`) | 10분
| 2부 | 모듈 1 — Red Hat build of Keycloak (`15-rhbk-mfa.adoc`) | 15분
| 2부 | 모듈 2 — ZTWIM (`16-ztwim.adoc`) | 10분
| 2부 | 모듈 3 — RHACS (`17-acs.adoc`) | 15분
| 끝 | Wrap Up (`99-conclusion.adoc`) | 5분
|===

목차 노출은 `default-site.yml` / `site.yml` 의 `module_enable_*` 로 결정됩니다.
pnu-ws 에서는 `install, appmgmt, ingress, netsec, debugging, gitops, security, ztwim` 이 `true` 입니다.

== 사전 준비 (한 줄 실행)

bastion 에서 cluster-admin 으로 `oc login` 한 뒤 실행합니다.

[source,bash]
----
bash <(curl -sL https://raw.githubusercontent.com/justone0127/OpenShift_Day_Ops_Korean-demo/pnu-ws/setup-scripts/pnu-ws-scripts/setup-pnu-ws.sh)
----

`setup-pnu-ws.sh` 는 저장소를 `$HOME/OpenShift_Day_Ops_Korean-demo` (pnu-ws) 에 clone/갱신한 뒤 다음을 차례로 수행합니다.

. *1부 준비* — `setup-core-ops.sh gitops`: OpenShift GitOps Operator 가 없으면 설치하고 ArgoCD 준비를 기다립니다.
. *2부 준비* — `setup-security-track.sh all`: 보안 트랙(RHBK / ZTWIM / RHACS) 실습 환경 배포.
. *매뉴얼 전환* — `switch-showroom-pnu-ws.sh`: Showroom 이 pnu-ws 브랜치를 보도록 바꾸고 재빌드.
. *점검* — `setup-core-ops.sh check`: 01~06 실습 조건 점검.

액션별 실행:

[source,bash]
----
URL=https://raw.githubusercontent.com/justone0127/OpenShift_Day_Ops_Korean-demo/pnu-ws/setup-scripts/pnu-ws-scripts

bash <(curl -sL $URL/setup-pnu-ws.sh) all          # 전체 (기본값)
bash <(curl -sL $URL/setup-pnu-ws.sh) env          # 실습 환경만 (1부 + 2부)
bash <(curl -sL $URL/setup-pnu-ws.sh) showroom     # 매뉴얼만 pnu-ws 로 전환
bash <(curl -sL $URL/setup-pnu-ws.sh) status       # 점검 + 상태 확인
bash <(curl -sL $URL/setup-pnu-ws.sh) cleanup      # 참가자 실습 리소스 정리
bash <(curl -sL $URL/setup-pnu-ws.sh) cleanup-all  # + 보안 트랙 공통 구성요소까지 정리

# 개별 스크립트
bash <(curl -sL $URL/switch-showroom-pnu-ws.sh)            # 매뉴얼 전환 (네임스페이스 자동 탐색)
bash <(curl -sL $URL/switch-showroom-pnu-ws.sh) --status   # 현재 Showroom 설정 확인
bash <(curl -sL $URL/setup-core-ops.sh) check              # 1부 조건 점검
----

== 매뉴얼 전환 스크립트가 하는 일

`switch-showroom-pnu-ws.sh`

. showroom Deployment 의 `git-cloner`(initContainer) / `content` 컨테이너의
  `GIT_REPO_URL` / `GIT_REPO_REF` 를 이 저장소의 `pnu-ws` 로 바꿉니다.
. `workshop-vars` ConfigMap 이 있으면 `MODULE_ENABLE_*` 를 pnu-ws 구성으로 맞춥니다
  (RHDP 카탈로그에서 01~06 을 끈 채 프로비저닝했더라도, 나중에 `inject-env-vars.sh` 가 다시 돌 때 목차가 바뀌지 않도록).
. pod 를 다시 띄워 clone → Antora 빌드를 다시 수행합니다. 이미 pnu-ws 를 보고 있으면 재시작만 합니다.

포크를 쓴다면 `SHOWROOM_REPO_URL=<포크 주소>` 를 앞에 붙입니다.

== 1부 진행 시 주의점

* *참가자 1인 1클러스터 기준*입니다. 1부 모듈은 고정 네임스페이스(`app-management`, `debug-lab` 등)와
  클러스터 범위 리소스(AdminNetworkPolicy)를 쓰므로, 클러스터 하나를 여러 명이 공유하면 서로 충돌합니다.
* *04/05 의 스크립트*는 Showroom 터미널에서 `raw.githubusercontent.com`(rhpds/openshift-days-ops-showroom)을 받아 실행합니다.
  외부 접근이 막힌 환경이면 `setup-core-ops.sh check` 에서 WARN 으로 표시됩니다.
* *06 GitOps* 는 ArgoCD UI 에 "Log in via OpenShift" 로 로그인합니다. admin 이 `cluster-admins` 그룹에 없으면
  UI 에서 Application 이 보이지 않을 수 있습니다 — `check` 가 경고하며, 필요하면
  `oc adm groups add-users cluster-admins admin` 으로 추가합니다.
* 각 1부 모듈 끝의 *정리* 명령을 참가자가 건너뛰었다면 `setup-pnu-ws.sh cleanup` 으로 한꺼번에 지울 수 있습니다.
