= 보안 트랙 진행자 가이드 (모듈 15/16/17)
:toc: left
:toclevels: 2

레드페이 침해사고 시나리오로 묶인 세 모듈
(Red Hat build of Keycloak → Zero Trust Workload Identity Manager → Red Hat Advanced Cluster Security)의
진행자용 문서입니다. 참가자에게 공개하지 마십시오 — 퀴즈 정답이 포함되어 있습니다.

== 시나리오 요약

잘 돌아가던 레드페이 결제 시스템에서 새벽 시간대에 요청 급증 알림이 울립니다.
들어가 보니 **사용자 계정이 털렸습니다** — 다중 인증(MFA)을 쓰지 않았기 때문입니다.

[cols="1,2,2",options="header"]
|===
| 공격 단계 | 일어난 일 | 방어선 (모듈)

| 1단계
| 유출된 비밀번호 하나로 `ops-admin` 계정 로그인 (MFA 미적용)
| *15 — Red Hat build of Keycloak* : OTP 기반 MFA 강제

| 2단계
| 내부 대역에서 온 요청이라는 이유로 모든 서비스가 공격자를 신뢰
| *16 — ZTWIM* : 내부 요청도 믿지 않는다 — 워크로드 신원 기반 mTLS

| 3단계
| `latest` 태그 이미지 안의 RCE 취약 라이브러리로 컨테이너 장악
| *17 — RHACS* : 탐지(Inform)에 머물던 정책을 차단(Enforce)으로 전환
|===

핵심 메시지: **레드페이는 필요한 보안 솔루션을 이미 도입했지만 제대로 적용하지 않았다.**
이 트랙은 그 보안을 "이제라도 제대로 켜서" 레드페이가 더 안전하게 결제 서비스를 하도록 만드는 과정입니다.

설계 원칙은 **"긴 YAML을 붙여넣지 않는다"** 입니다.
실습 환경은 진행자가 전부 사전 배포하며, 참가자는 관찰과 판단에 시간을 씁니다.

== 사전 준비 (진행자)

=== 필수 조건

* OpenShift 4.14+ 클러스터, `cluster-admin` 권한
* `redhat-operators` CatalogSource 사용 가능 (15번 — RHBK Operator 설치)
* **ZTWIM 오퍼레이터** 사전 설치 (16번 모듈)
* **RHACS** Central + SecuredCluster 사전 설치 (17번 모듈)
* bastion에 `oc`, `git`, `curl`, `python3`
* 참가자 스마트폰에 TOTP 앱 (Google Authenticator / Microsoft Authenticator / FreeOTP 등) —
  **워크샵 공지 시 미리 설치를 안내**하십시오.

[WARNING]
====
같은 클러스터에서 `08-oidc-authentication` 모듈(`module_enable_oidc`)을 함께 진행하지 마십시오.
두 모듈 모두 `rhbk` namespace와 `rhbk` Identity Provider 이름을 사용하므로, 한쪽의 정리 스크립트가 다른 쪽 환경을 삭제합니다.
보안 트랙 행사에서는 `module_enable_oidc: 'false'` 로 두는 것을 권장합니다.
====

=== 실행

[source,bash]
----
cd ~/
git clone -b ops-sc https://github.com/justone0127/OpenShift_Day_Ops_Korean-demo.git
cd OpenShift_Day_Ops_Korean-demo/setup-scripts/security-track-scripts
./setup-security-track.sh all
----

약 10~15분 소요됩니다. 대부분 RHBK Operator 설치, OAuth pod 재시작, SPIRE 구성 대기 시간입니다.

[IMPORTANT]
====
**워크샵 시작 전에 미리 실행해 두십시오.** 참가자는 이 스크립트를 실행하지 않습니다.

RHDP/AgnosticV 환경이라면 이 스크립트를 프로비저닝 단계에 포함시키는 것이 가장 좋습니다.
====

=== 15번 모듈(RHBK MFA) 사전 구성 상세

`setup-scripts/rhbk-config-scripts/setup-rhbk-mfa-lab.sh` 가 다음을 준비합니다.
`setup-security-track.sh all` (또는 `rhbk`)이 내부에서 호출하며, 단독 실행도 가능합니다.

[cols="1,3",options="header"]
|===
| 항목 | 내용

| RHBK Operator
| namespace `rhbk`, channel `stable-v26`

| Keycloak 인스턴스
| `keycloak` (dev-file DB, 1 instance) + edge Route `keycloak`

| Realm `redpay`
| 표시 이름 *RedPay*, **셀프 등록(Register) 허용**, brute-force 보호,
  TOTP 정책(HmacSHA1 / 6자리 / 30초 — 일반 OTP 앱과 호환),
  SSO 세션 유휴 60초 (로그아웃 후 재로그인 시 OTP 입력을 바로 보여 주기 위함)

| Required action *Configure OTP*
| *Enabled* = On, *Set as default action* = **Off** (참가자가 실습에서 직접 켭니다)

| OIDC client `openshift`
| redirect URI = `https://oauth-openshift.<apps-domain>/oauth2callback/rhbk`, groups mapper 포함

| OpenShift OAuth
| `openshift-config/rhbk-client-secret` 생성, OAuth에 `rhbk` Identity Provider **추가**
  (기존 htpasswd 등 다른 IdP는 유지). ingress 인증서가 자체 서명이면 `rhbk-ca` ConfigMap 자동 등록
|===

[source,bash]
----
cd ~/OpenShift_Day_Ops_Korean-demo/setup-scripts/rhbk-config-scripts

./setup-rhbk-mfa-lab.sh all       # 전체 구성
./setup-rhbk-mfa-lab.sh status    # 준비 상태 점검 (Configure OTP 상태, 등록 사용자 수 포함)
./setup-rhbk-mfa-lab.sh info      # Keycloak 콘솔 URL / admin 계정 출력
./setup-rhbk-mfa-lab.sh reset     # 회차 사이 리셋: 등록된 사용자 전체 삭제 + Default action 을 Off 로 복원
./setup-rhbk-mfa-lab.sh cleanup   # OAuth 에서 rhbk 제거 + rhbk namespace 삭제
----

[TIP]
====
실습 시간을 줄이고 싶다면 *Set as default action* 까지 미리 켜 둘 수 있습니다:

[source,bash]
----
RHBK_OTP_DEFAULT_ACTION=true ./setup-rhbk-mfa-lab.sh realm
----

이 경우 참가자 가이드 2단계는 "확인"만 하게 됩니다.
====

=== 확인

[source,bash]
----
cd ~/OpenShift_Day_Ops_Korean-demo/setup-scripts/security-track-scripts
./setup-security-track.sh status
----

다음이 모두 준비되어 있어야 합니다:

* 15번: RHBK Operator, Keycloak pod Ready, Realm `redpay`, Configure OTP `Enabled=True`,
  `openshift-config/rhbk-client-secret`, OAuth identity provider `rhbk` — 모두 ✓
* 16번: `postgresql-spiffe` / `postgresql-spiffe-client` 각각 `2/2 Running`
* 17번: `redpay` namespace에 `payment-api`, `payment-api-secure` / `~/redpay-lab/` 에 매니페스트 사본 2개

마지막으로 **OpenShift 콘솔 로그아웃 → 로그인 화면에 `rhbk` 가 보이는지** 직접 확인하십시오.

=== 부분 실행

[source,bash]
----
./setup-security-track.sh rhbk     # 15번만
./setup-security-track.sh ztwim    # 16번만
./setup-security-track.sh acs      # 17번만
----

=== 정리

[source,bash]
----
./setup-security-track.sh cleanup
----

NOTE: RHACS 정책의 Enforcement 설정은 스크립트가 되돌리지 않습니다.
콘솔에서 *Policy Management* → *Latest tag* → *Response method* → `Inform only` 로 수동 복원하십시오.

== 진행 시 주의점

=== 15번 모듈 (Red Hat build of Keycloak)

* **realm 선택 실수가 가장 흔합니다.** `master` realm에서 Required actions를 바꾸면 아무 효과가 없습니다.
  사이드바 상단 *Current realm* 이 `redpay` 인지 먼저 확인시키십시오.
* **Register 화면의 네 필드(Username / Email / First name / Last name)를 모두 채워야 합니다.**
  하나라도 비면 OpenShift 로그인 단계에서 원인이 불분명한 오류가 납니다.
* 같은 클러스터를 여러 참가자가 공유한다면 **Username이 겹치지 않도록** 이니셜 등을 붙이게 하십시오.
* **`Invalid authenticator code`** — 대부분 스마트폰 시간이 수동 설정되어 있거나, 숫자가 바뀌는 순간에 입력한 경우입니다.
* **로그아웃 후 다시 로그인했는데 OTP를 묻지 않는 경우** — Keycloak SSO 세션이 아직 살아 있는 것입니다.
  1분 기다리거나 시크릿 창을 쓰게 하십시오.
* **Showroom 임베디드 탭에서 Keycloak 로그인 화면이 깨져 보이면** OCP Console을 새 브라우저 탭으로 열게 하십시오.
* 이 모듈의 감정적 정점은 **5단계에서 비밀번호를 정확히 넣었는데도 OTP 화면에서 멈추는 순간**입니다.
  "공격자도 여기까지는 왔을 겁니다"라고 한 번 짚어 주면 임팩트가 커집니다.
* 회차를 반복한다면 사이마다 `./setup-rhbk-mfa-lab.sh reset` 으로 사용자와 Default action을 초기화하십시오.

=== 16번 모듈 (ZTWIM)

* SPIRE 구성이 가장 무겁습니다. **반드시 사전에 배포**해 두십시오.
* `attacker` pod 실습에서 이미지 pull에 시간이 걸릴 수 있습니다(`registry.redhat.io` 인증 필요).
  실패하면 `oc get pod attacker -n postgresql-spiffe-client -o yaml | grep -A5 status` 로 확인하십시오.
* `attacker` pod는 `latest` 태그 이미지를 씁니다. 17번 모듈에서 RHACS *Latest tag* 정책을 Enforce로 바꾼 **뒤에는**
  이 pod가 차단됩니다. 모듈 순서(16 → 17)를 지키면 문제없습니다.
* 이 모듈의 감정적 정점은 **`attacker` pod가 거부되는 순간**입니다.
  그 직전에 "이 pod는 같은 namespace에 있고, 포트도 열려 있고, NetworkPolicy도 안 막습니다"를
  한 번 짚어 주면 임팩트가 커집니다.

=== 17번 모듈 (RHACS)

* **위반 사항 표시 지연** — RHACS가 워크로드를 수집하고 평가하는 데 30초~1분이 걸립니다.
  참가자가 "안 보여요"라고 하면 먼저 새로고침을 안내하십시오.
* **정책 이름은 RHACS 버전마다 조금씩 다릅니다.** `Latest tag` 는 검색창에 `latest` 로 찾도록 안내하는 것이 안전합니다.
* **정책이 Disabled 상태일 수 있습니다.** Enforce로 바꾸기 전에 Enable부터 확인시키십시오.
* **차단 시연이 실패하는 경우** — 대부분 admission controller 문제입니다:
+
[source,bash]
----
oc get securedcluster -n stackrox -o jsonpath='{.items[0].spec.admissionControl}{"\n"}'
----
+
`listenOnCreates: true` 가 없으면 `./setup-security-track.sh acs` 를 다시 실행하십시오.
* **`privileged: true` 는 매니페스트에서 의도적으로 뺐습니다.** OpenShift의 기본 SCC(`restricted-v2`)가
  이를 먼저 차단해서 pod가 아예 뜨지 않기 때문입니다. 질문이 나오면
  "OpenShift SCC가 이미 한 겹 막아 주고 있고, RHACS는 그 위의 계층"이라고 설명하시면 좋습니다.

== 퀴즈 정답 및 해설 요약

가이드 안에 접기(collapsible) 블록으로 해설이 포함되어 있습니다.
아래는 진행자가 빠르게 참조할 요약본입니다.

=== 인트로 (15-00) — 워밍업 4문항

[cols="1,1,4",options="header"]
|===
| 문항 | 정답 | 진행자가 강조할 지점

| Q0-1
| *(B)*
| 비밀번호 강도 ≠ 유출 내성. 인증 요소가 하나뿐이면 유출 즉시 공격자와 사용자를 구별할 수 없다. MFA = 아는 것 + 가진 것.

| Q0-2
| *(C)*
| QR 코드 = 비밀 키(seed). 앱과 서버가 "비밀 키 + 현재 시각"으로 같은 숫자를 계산. 오프라인 동작, 30초마다 변경.

| Q0-3
| *(B)*
| M&M 보안 — 한 번만 뚫리면 되는 구조. 횡적 이동을 막을 계층이 없다.

| Q0-4
| *(B)*
| CI 스캔은 시점의 스냅샷. 클러스터는 계속 살아 있고 CVE는 매일 새로 나온다.
|===

=== 15번 (Red Hat build of Keycloak) — 2문항

[cols="1,1,4",options="header"]
|===
| 문항 | 정답 | 진행자가 강조할 지점

| 퀴즈 1
| *(B)*
| *Enabled* = "쓸 수 있다", *Set as default action* = "반드시 쓴다".
  **"보안 기능을 가진 것"과 "적용한 것"의 차이** — 트랙 전체의 핵심 메시지와 직결됩니다.

| 퀴즈 2
| *(B)*
| TOTP는 짧은 시간 창 + 1회용. 다만 실시간 중계형 피싱(AitM)에는 취약하므로
  고위험 계정은 WebAuthn/Passkey도 검토. "MFA는 만능은 아니지만 유출 비밀번호 공격은 확실히 막는다."
|===

=== 16번 (ZTWIM) — 2문항

[cols="1,1,4",options="header"]
|===
| 문항 | 정답 | 진행자가 강조할 지점

| 퀴즈 1
| *(B)*
| 짧은 수명의 두 효과 — 악용 창 축소 + 폐기(CRL/OCSP) 인프라 회피.
  "폐기가 그냥 기다리기가 된다"는 표현이 잘 먹힙니다. 자동 갱신이 전제 조건.

| 퀴즈 2
| *(B)*
| label은 **자기 신고**라 위조 가능. SVID는 SPIRE가 노드에서 검증 후 발급.
  NetworkPolicy와 SPIFFE는 대체가 아니라 **계층**이라는 결론으로 마무리하십시오.
|===

=== 17번 (RHACS) — 3문항

[cols="1,1,4",options="header"]
|===
| 문항 | 정답 | 진행자가 강조할 지점

| 퀴즈 1
| *(B)*
| 두 가지가 겹쳐 있다 — (1) 시간이 흘러 새 CVE가 나왔고 (2) 배포 방식의 문제는 이미지 스캐너가 볼 수 없는 영역이다.

| 퀴즈 2
| *(B)*
| Fixable = 패치가 이미 존재. 투입 대비 효과가 가장 높은 작업을 골라내는 필터.
  Fixable이 아닌 것도 여전히 위험하며 완화 조치로 대응한다는 점을 덧붙이면 좋습니다.

| 퀴즈 3
| *(C)*
| 사람의 협조 → 플랫폼의 강제. **(D)는 흔한 오답** — Deploy enforcement는 새 요청만 막고
  기존 워크로드를 소급 제거하지 않습니다. 실습에서 `oc delete` 를 먼저 한 이유입니다.
|===

== 시간이 부족할 때

50분을 다 쓰기 어려운 경우의 우선순위입니다.

. **반드시 유지** — 15번 4~5단계(OTP 등록과 재로그인 시 OTP 요구), 16번의 `attacker` pod 거부 실습,
  17번 3~4단계(탐지→차단 전환과 실제 거부). 이 세 장면이 트랙 전체의 임팩트를 만듭니다.
. **줄일 수 있음** — 15번 6단계(관리자 화면 확인), 17번 2단계(CVE 확인)는 진행자 시연으로 대체 가능.
. **퀴즈** — 인트로 4문항은 각자 읽고 넘어가게 하고, 모듈별 퀴즈만 함께 다루는 방식도 좋습니다.
