= Red Hat build of Keycloak — 다중 인증(MFA)
:page-toclevels: 1

== 모듈 개요

**소요 시간:** 15분 +
**형식:** 핸즈온 실습 (콘솔 중심) +
**대상 참석자:** Security Engineers, Platform Engineers, IT Operations

include::partial$console-access.adoc[]

[IMPORTANT]
.레드페이 침해사고 — 1단계 공격
====
새벽 3시, 결제 API를 두드린 것은 **정상적으로 로그인한 `ops-admin` 계정**이었습니다.
비밀번호는 다른 곳에서 유출된 그대로였고, 레드페이의 Keycloak에는 다중 인증(MFA)이 **켜져 있지 않았습니다.**

이 모듈에서 막을 공격입니다. 배경은 xref:15-00-security-story.adoc[보안 트랙 시작] 페이지에 있습니다.
====

**Red Hat build of Keycloak (RHBK)** 은 Red Hat이 지원하는 Keycloak 배포판으로,
OpenID Connect(OIDC) / SAML 기반의 통합 인증(SSO)과 다중 인증(MFA)을 제공합니다.
이 실습 환경에서는 RHBK가 이미 OpenShift의 Identity Provider(`rhbk`)로 연동되어 있습니다.

[NOTE]
====
Keycloak 설치, `redpay` realm 생성, OpenShift OAuth 연동은 **진행자가 사전에 준비**해 두었습니다.
여러분은 MFA를 실제로 **켜고**, 새 사용자로 **OTP를 등록해 로그인**하는 데 집중합니다.
====

== 학습 목표

이 모듈을 마칠 때쯤 여러분은 다음을 수행할 수 있게 됩니다:

* Keycloak 콘솔에서 *Configure OTP* Required action이 켜져 있는지 확인하고, 새 사용자에게 OTP 등록을 강제합니다
* OpenShift 로그인 화면에서 `rhbk` 를 선택해 새 사용자를 직접 등록합니다
* QR 코드를 OTP 앱에 등록하고, 토큰 값을 입력해 OpenShift에 로그인합니다
* 다시 로그인할 때 **비밀번호만으로는 로그인할 수 없음**을 확인합니다

== 사전 준비 — OTP 앱

스마트폰에 TOTP(시간 기반 일회용 비밀번호)를 지원하는 앱이 하나 필요합니다. 이미 쓰고 있는 앱이 있다면 그대로 사용하십시오.

* Google Authenticator
* Microsoft Authenticator
* FreeOTP (Red Hat이 후원하는 오픈소스 앱)

TIP: 스마트폰을 사용할 수 없다면 진행자에게 알려 주십시오. TOTP를 지원하는 데스크톱 앱이나 브라우저 확장으로도 실습할 수 있습니다.

== 1단계 — Keycloak 콘솔 접속

.실습 절차
. 터미널에서 Keycloak 콘솔 주소와 관리자 계정을 확인합니다:
+
[source,bash,role="execute"]
----
echo "Keycloak URL: https://$(oc get route keycloak -n rhbk -o jsonpath='{.spec.host}')/admin/master/console/"
echo "Username: $(oc get secret keycloak-initial-admin -n rhbk -o jsonpath='{.data.username}' | base64 -d)"
echo "Password: $(oc get secret keycloak-initial-admin -n rhbk -o jsonpath='{.data.password}' | base64 -d)"
----
+
. 출력된 URL을 **새 브라우저 탭**에서 열고, 위의 Username / Password로 로그인합니다.
. 왼쪽 상단의 realm 선택 영역(또는 *Manage realms*)에서 **`redpay`** realm을 선택합니다.
+
[IMPORTANT]
====
반드시 `redpay` realm에서 작업하십시오. `master` realm은 Keycloak 자체 관리용입니다.
왼쪽 사이드바 상단에 *Current realm* 으로 `redpay` (표시 이름: RedPay)가 보이면 됩니다.
====

== 2단계 — Configure OTP 설정 확인

Keycloak에서 OTP 등록은 **Required action**(사용자가 로그인 과정에서 반드시 수행해야 하는 작업)으로 동작합니다.

.실습 절차
. 왼쪽 메뉴에서 *Authentication* 을 클릭합니다.
. 상단의 *Required actions* 탭을 클릭합니다.
. *Configure OTP* 행을 찾아 다음을 확인합니다:
+
image::rhbk-mfa-required-actions.png[Keycloak Authentication Required actions 탭에서 Configure OTP가 Enabled On 인 화면, link=self, window=blank, width=100%]
+
[cols="1,1,3",options="header"]
|===
| 항목 | 설정 값 | 의미

| *Enabled*
| **On**
| 이 realm에서 OTP 등록 기능을 사용할 수 있습니다. Off이면 **On으로 켭니다.**

| *Set as default action*
| **On** 으로 변경
| 새로 생성되는 **모든 사용자**가 첫 로그인 시 OTP를 반드시 등록하도록 강제합니다.
|===
+
. *Configure OTP* 행의 *Set as default action* 토글을 **On** 으로 켭니다.
  화면 상단에 `Updated required action successfully` 메시지가 표시됩니다.

[NOTE]
====
*Enabled* 만 켜져 있으면 "OTP를 등록할 수 **있는**" 상태일 뿐입니다.
레드페이가 바로 이 상태였습니다 — 기능은 있었지만, 아무도 등록하지 않았습니다.

*Set as default action* 까지 켜야 "OTP를 등록하지 않으면 로그인할 수 **없는**" 상태가 됩니다.
한 번 OTP를 등록한 사용자는 이후 모든 로그인에서 비밀번호와 함께 OTP를 요구받습니다.
====

=== 🧠 퀴즈 1

*Configure OTP* 의 *Enabled* 는 On인데 *Set as default action* 은 Off인 상태라면, 새로 가입한 사용자는 어떻게 됩니까?

[none]
* (A) 첫 로그인 시 OTP 등록 화면이 반드시 나타난다
* (B) 비밀번호만으로 로그인할 수 있으며, 본인이 원할 때만 OTP를 등록한다
* (C) OTP를 등록하기 전까지는 로그인이 차단된다
* (D) 관리자가 승인해야만 로그인할 수 있다

.정답 및 해설 보기
[%collapsible]
====
**정답: (B)**

*Enabled* 는 "이 기능을 쓸 수 있다"는 뜻입니다. 사용자가 계정 설정에서 직접 OTP를 추가하거나,
관리자가 특정 사용자에게 개별적으로 OTP 등록을 요구할 수 있게 됩니다.

하지만 **강제하지 않으면 대부분은 등록하지 않습니다.** 불편하니까요.
레드페이의 `ops-admin` 이 바로 그런 계정이었습니다.

*Set as default action* 을 켜면 새 사용자 전원에게 OTP 등록이 **기본으로 부여**됩니다.
"보안 기능을 갖고 있는 것"과 "보안 기능이 적용되어 있는 것"의 차이입니다.
====

== 3단계 — OpenShift 로그인 화면에서 새 사용자 등록

이제 레드페이의 새 운영자가 되어 OpenShift에 처음 로그인해 봅니다.

.실습 절차
. **OCP Console** 탭에서 우측 상단의 사용자 이름을 클릭하고 *Log out* 을 선택합니다.
. 로그인 화면에 Identity Provider 목록이 표시됩니다. **`rhbk`** 를 클릭합니다.
+
TIP: 목록이 보이지 않고 이전 세션으로 바로 로그인된다면, OCP Console 탭 옆의 **새로고침 버튼** (원형 화살표)을 클릭하십시오.
+
. **RedPay** 로그인 화면(Keycloak)으로 이동합니다. 로그인 폼 아래의 **Register** 링크를 클릭합니다.
. 사용자 정보를 입력합니다. **네 가지 필드를 모두 채워야 합니다.**
+
[cols="1,2",options="header"]
|===
| 필드 | 입력 예시

| *Username*
| `redpay-ops-<본인 이니셜>` (예: `redpay-ops-hgd`)

| *Email*
| `redpay-ops-hgd@example.com`

| *First name* / *Last name*
| 본인 이름 또는 임의의 값

| *Password* / *Confirm password*
| 기억할 수 있는 비밀번호 (예: `RedPay2026!`)
|===
+
. *Register* 를 클릭합니다.

== 4단계 — QR 코드로 OTP 앱 등록

*Register* 를 누르면 곧바로 로그인되지 않고 **Mobile Authenticator Setup** 화면이 나타납니다.
2단계에서 켠 *Set as default action* 이 동작한 것입니다.

.실습 절차
. 스마트폰에서 OTP 앱을 열고 **계정 추가(+)** → **QR 코드 스캔** 을 선택합니다.
. 화면에 표시된 **QR 코드**를 스캔합니다.
+
앱에 `RedPay` (또는 `redpay`) 항목과 함께 **6자리 숫자**가 표시됩니다. 이 숫자는 30초마다 바뀝니다.
+
TIP: QR 코드를 스캔할 수 없다면 화면의 *Unable to scan?* 을 클릭하십시오. 앱에 직접 입력할 수 있는 키 문자열이 표시됩니다.
+
. 앱에 표시된 6자리 숫자를 *One-time code* 칸에 입력합니다.
. *Device Name* 에 기기를 구분할 이름을 입력합니다 (예: `my-phone`). 선택 사항입니다.
. *Submit* 을 클릭합니다.
+
[NOTE]
====
`Invalid authenticator code` 오류가 나오면 앱의 숫자가 바뀐 직후의 **새 값**을 입력해 다시 시도하십시오.
계속 실패하면 스마트폰의 시간이 **자동 설정**으로 되어 있는지 확인하십시오. TOTP는 시각을 기준으로 계산됩니다.
====
+
. OpenShift 콘솔로 돌아오고, 우측 상단에 방금 등록한 사용자 이름이 표시됩니다.

[NOTE]
====
새로 등록한 사용자에게는 아직 아무 프로젝트 권한도 없으므로 콘솔이 비어 있는 것이 정상입니다.
이 모듈의 목적은 **"누가 로그인할 수 있는가"** 를 통제하는 것입니다. 권한(RBAC) 부여는 별도의 단계입니다.
====

== 5단계 — 다시 로그인: 이제 비밀번호만으로는 안 된다

OTP 등록은 한 번이지만, 효과는 **모든 로그인**에 적용됩니다. 직접 확인해 봅니다.

.실습 절차
. **OCP Console** 탭에서 우측 상단의 사용자 이름 → *Log out* 을 선택합니다.
. **약 1분**을 기다립니다.
+
NOTE: OpenShift에서 로그아웃해도 Keycloak의 SSO 세션은 잠시 유지됩니다. 실습 환경은 SSO 세션 유휴 시간을 1분으로 짧게 설정해 두었습니다.
바로 확인하고 싶다면 브라우저의 **시크릿(프라이빗) 창**에서 OCP Console 주소를 열어도 됩니다.
+
. 로그인 화면에서 **`rhbk`** 를 선택하고, 3단계에서 만든 *Username* / *Password* 로 로그인합니다.
. 비밀번호를 입력해도 바로 들어가지지 않고, **One-time code** 입력 화면이 나타납니다.
. 먼저 **틀린 숫자**(예: `000000`)를 입력해 봅니다. `Invalid authenticator code` 로 거부됩니다.
. OTP 앱에 표시된 **현재 6자리 숫자**를 입력하고 *Sign In* 을 클릭합니다.
. OpenShift 콘솔에 로그인됩니다.

[IMPORTANT]
====
**이것이 레드페이에서 일어나지 않았던 일입니다.**

공격자는 `ops-admin` 의 비밀번호를 **정확히** 알고 있었습니다.
하지만 이 화면 앞에서 멈췄을 것입니다. 6자리 숫자는 운영자의 스마트폰 안에서만, 30초마다 새로 만들어지니까요.
====

=== 🧠 퀴즈 2

공격자가 피싱 사이트로 사용자의 비밀번호와 **그 순간의 OTP 6자리**를 함께 가로챘습니다. 다음 중 **맞는** 설명은?

[none]
* (A) OTP는 한 번 쓰면 끝이므로 어떤 경우에도 안전하다
* (B) 가로챈 OTP는 보통 30초 안팎의 짧은 시간에만 유효하며, 그 안에 실시간으로 악용하지 않으면 쓸모가 없다
* (C) 비밀번호와 OTP를 모두 가로챘으므로 공격자는 앞으로 언제든 로그인할 수 있다
* (D) OTP 앱의 QR 코드도 함께 유출된 것이다

.정답 및 해설 보기
[%collapsible]
====
**정답: (B)**

TOTP 값은 짧은 시간 창에서만 유효하고, 한 번 사용된 값은 재사용할 수 없습니다.
그래서 공격자는 **그 30초 안에 실시간으로** 로그인해야 하고, 다음 로그인에는 또 새 숫자가 필요합니다.
(C)처럼 "앞으로 언제든"은 불가능합니다. 다음 숫자를 만들 비밀 키는 사용자 스마트폰에만 있으니까요.

다만 (A)처럼 "어떤 경우에도 안전"하지는 않습니다. 실시간 중계형 피싱(AitM)은 그 짧은 창을 노립니다.
그래서 보안 요구 수준이 더 높은 계정에는 피싱 방지형 인증(WebAuthn / Passkey)을 함께 검토합니다.
RHBK는 같은 *Required actions* 화면에서 *Webauthn Register* 같은 방식도 지원합니다.

MFA는 만능이 아니지만, **유출된 비밀번호만으로 들어오는 공격** — 레드페이 사고의 1단계 — 는 확실히 막습니다.
====

== 6단계 — 관리자 화면에서 결과 확인 (선택)

.실습 절차
. Keycloak 콘솔(`redpay` realm)에서 왼쪽 메뉴의 *Users* 를 클릭합니다.
. 3단계에서 만든 사용자를 클릭하고 *Credentials* 탭을 엽니다.
. `password` 와 함께 **`otp`** 자격 증명이 등록되어 있는 것을 확인합니다. *Device Name* 에 입력한 이름도 보입니다.
+
TIP: 사용자가 스마트폰을 잃어버린 경우, 관리자는 이 화면에서 `otp` 자격 증명을 **삭제**하면 됩니다. 사용자는 다음 로그인 때 새 기기로 OTP를 다시 등록하게 됩니다.

== 관리자 계정으로 복귀

다음 모듈은 클러스터 관리자 권한이 필요합니다.

.실습 절차
. **OCP Console** 탭에서 *Log out* 한 뒤, 기존 관리자 계정의 Identity Provider(예: `htpasswd`)를 선택하고 아래 자격 증명으로 로그인합니다.
+
[cols="1,1"]
|===
| *Username:* | {openshift_cluster_admin_username}
| *Password:* | {openshift_cluster_admin_password}
|===
+
. 터미널도 관리자로 로그인되어 있는지 확인합니다:
+
[source,bash,role="execute"]
----
oc whoami
----

== 학습 내용 요약

* **비밀번호는 "아는 것" 하나뿐입니다.** 아무리 복잡해도 유출되면 공격자와 사용자를 구별할 수 없습니다.
* **MFA는 서로 다른 종류의 증거를 요구합니다.** 비밀번호(아는 것) + OTP 앱(가진 것).
* Keycloak에서 *Configure OTP* 를 **Enabled** 로 두는 것은 "쓸 수 있다", **Set as default action** 까지 켜는 것은 "반드시 쓴다"입니다.
* TOTP는 QR 코드로 한 번 공유한 비밀 키와 현재 시각으로 계산되며, 30초마다 바뀝니다.
* OpenShift는 OIDC로 Keycloak에 인증을 위임하므로, **Keycloak에서 켠 MFA가 OpenShift 로그인에 그대로 적용**됩니다. OpenShift 쪽 설정 변경은 필요 없습니다.

== 다음 단계

1단계 공격은 막았습니다. 이제 공격자는 운영자 계정으로 들어올 수 없습니다.

하지만 레드페이 사고에서 피해를 회원 DB까지 넓힌 것은 **"내부에서 온 요청이면 믿는다"** 는 가정이었습니다.
어떤 경로로든 공격자가 한 번 내부에 들어오면, 그 가정은 다시 무너집니다.

xref:16-ztwim.adoc[다음 모듈]에서 2단계 공격을 다룹니다.
