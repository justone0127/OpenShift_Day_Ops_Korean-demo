= Red Hat build of Keycloak — 다중 인증(MFA)

== 모듈 개요

**소요 시간:** 15분 +
**형식:** 핸즈온 실습 (콘솔 + 스마트폰 앱 또는 Chrome 확장 프로그램) +
**대상 참석자:** Security Engineers, Platform Engineers, IT Operations

[IMPORTANT]
.RedPay 침해사고 — 1단계 공격
====
새벽에 결제 데이터를 쓸어 간 것은 **정상적으로 로그인한 운영자 계정 `ops-admin`** 이었습니다.
비밀번호는 다른 곳에서 유출된 그대로였고, 여러분의 Keycloak에는 MFA 기능이 있었지만
**아무에게도 강제되지 않았습니다.**

이 모듈에서 여러분이 적용할 첫 번째 보안 통제입니다.
배경은 xref:15-00-security-story.adoc[보안 트랙 시작] 페이지에 있습니다.
====

**Red Hat build of Keycloak (RHBK)** 은 Red Hat이 지원하는 Keycloak 배포판으로,
OpenID Connect(OIDC)·SAML 기반의 통합 인증(SSO)과 다중 인증(MFA)을 제공합니다.

여러분의 클러스터에는 RHBK가 이미 설치되어 있고, OpenShift의 Identity Provider(`rhbk`)로 연동되어 있습니다.
RedPay의 상황과 똑같습니다 — **도구는 있습니다. 켜지 않았을 뿐입니다.**

== 학습 목표

이 모듈을 마칠 때쯤 여러분은 다음을 수행할 수 있게 됩니다:

* Keycloak 관리 콘솔에서 *Configure OTP* 설정을 확인하고, 새 사용자에게 OTP 등록을 **강제**합니다
* OpenShift 로그인 화면에서 `rhbk` 를 선택해 새 사용자를 직접 등록합니다
* QR 코드를 OTP 앱(또는 Chrome 확장 프로그램)에 등록하고, 토큰 값을 입력해 OpenShift에 로그인합니다

== 사전 준비 — OTP 앱

TOTP(시간 기반 일회용 비밀번호)를 만들어 주는 도구가 하나 필요합니다. 아래 두 방법 중 하나를 고르십시오.

[cols="1,2,2",options="header"]
|===
| 방법 | 준비할 것 | 이런 경우에

| *방법 A — 스마트폰 앱* (권장)
| 스마트폰에 아래 앱 중 하나 설치 +
  · Google Authenticator +
  · Microsoft Authenticator +
  · FreeOTP (Red Hat이 후원하는 오픈소스 앱)
| 스마트폰이 있는 경우. 실제 운영 환경과 같은 방식입니다.

| *방법 B — Chrome 확장 프로그램*
| Chrome에 *Authenticator* 확장 프로그램 설치 (아래 절차)
| 스마트폰이 없거나, 앱을 설치할 수 없는 경우
|===

이미 쓰고 있는 OTP 앱이 있다면 그대로 사용하셔도 됩니다.

=== 방법 B를 쓸 경우 — Chrome 확장 프로그램 설치

.실습 절차
. Chrome에서 Chrome 웹 스토어의 link:https://chrome.google.com/webstore/detail/authenticator/bhghoamapcdpbohphigoooaddinpkbai[Authenticator, window=blank] 페이지를 엽니다.
  (제작: authenticator.cc · 홈페이지 link:https://authenticator.cc[authenticator.cc, window=blank])
. *Chrome에 추가* → *확장 프로그램 추가* 를 클릭합니다.
. 주소창 오른쪽의 퍼즐 모양 아이콘(*확장 프로그램*)을 클릭하고, *Authenticator* 옆의 핀 아이콘을 눌러 **도구 모음에 고정**합니다.
  4단계에서 이 아이콘을 바로 눌러야 하므로 꼭 고정해 두십시오.

[NOTE]
====
확장 프로그램은 OTP 비밀 키를 **브라우저 안에** 보관합니다. 비밀번호와 같은 기기에 두 번째 인증 수단이 있는 셈이라,
실제 운영 환경에서는 별도 기기(스마트폰)의 앱을 쓰는 것이 더 안전합니다. 이 실습에서는 동작 원리를 확인하는 용도로 충분합니다.
====

== 1단계 — Keycloak 관리 콘솔 접속

.실습 절차
. 터미널에서 Keycloak 관리 콘솔 주소와 관리자 계정을 확인합니다:
+
[source,bash,role="execute"]
----
echo "Keycloak URL: https://$(oc get route keycloak -n rhbk -o jsonpath='{.spec.host}')/admin/master/console/#/redpay"
echo "Username:     $(oc get secret keycloak-initial-admin -n rhbk -o jsonpath='{.data.username}' | base64 -d)"
echo "Password:     $(oc get secret keycloak-initial-admin -n rhbk -o jsonpath='{.data.password}' | base64 -d)"
----
+
. 출력된 URL을 **새 브라우저 탭**에서 열고, 위의 Username / Password로 로그인합니다.
. 왼쪽 사이드바 맨 위의 *Current realm* 이 **`redpay`** 인지 확인합니다.
  다른 realm(`master`)이 보이면 *Manage realms* 를 눌러 `redpay` 를 선택하십시오.
+
[IMPORTANT]
====
반드시 `redpay` realm에서 작업하십시오. `master` realm은 Keycloak 자체를 관리하는 realm이라,
여기서 설정을 바꿔도 RedPay 사용자에게는 아무 효과가 없습니다.
====

== 2단계 — OTP 등록을 모든 사용자에게 강제

Keycloak에서 OTP 등록은 **Required action**(사용자가 로그인 과정에서 반드시 거쳐야 하는 작업)으로 동작합니다.

.실습 절차
. 왼쪽 메뉴에서 *Authentication* 을 클릭합니다.
. 상단의 *Required actions* 탭을 클릭합니다.
. *Configure OTP* 행(아래 그림의 빨간 상자)을 찾습니다. 지금은 다음과 같은 상태입니다:
+
image::rhbk-mfa-required-actions.png[RedPay realm 의 Authentication → Required actions 탭 — 빨간 상자로 표시한 Configure OTP 행. Enabled On, Set as default action Off 상태, link=self, window=blank, width=100%]
+
[cols="1,1,3",options="header"]
|===
| 항목 | 현재 상태 | 의미

| *Enabled*
| On
| 이 realm에서 OTP 등록 기능을 **쓸 수 있습니다**.

| *Set as default action*
| **Off**
| 새로 만들어지는 사용자에게 OTP 등록을 **요구하지 않습니다**.
|===
+
. *Configure OTP* 행의 *Enabled* 가 **On** 인지 확인합니다. Off라면 먼저 On으로 켭니다.
. 같은 행의 *Set as default action* 토글을 **On** 으로 켭니다.
  화면 위쪽에 `Updated required action successfully` 메시지가 잠깐 표시됩니다.
+
image::rhbk-mfa-default-action-on.png[Configure OTP 행의 Set as default action 토글을 On 으로 켠 화면 — 빨간 상자로 표시, link=self, window=blank, width=100%]
+
*Enabled* 와 *Set as default action* 이 모두 **On** 이면 완료입니다.

[NOTE]
====
*Enabled* 만 켜져 있는 상태는 "OTP를 등록할 **수 있는**" 상태일 뿐입니다.
RedPay가 바로 이 상태였습니다 — 기능은 있었지만, 등록한 사람은 아무도 없었습니다.

*Set as default action* 까지 켜야 "OTP를 등록하지 않으면 로그인할 **수 없는**" 상태가 됩니다.
한 번 OTP를 등록한 사용자는 이후 모든 로그인에서 비밀번호와 함께 OTP를 요구받습니다.
====

== 3단계 — OpenShift 로그인 화면에서 새 사용자 등록

이제 RedPay에 새로 합류한 운영자가 되어 OpenShift에 처음 로그인해 봅니다.

.실습 절차
. **OCP Console** 탭에서 오른쪽 위의 사용자 이름을 클릭하고 *Log out* 을 선택합니다.
. 로그인 화면에 Identity Provider 목록이 나타납니다. 지금까지 쓰던 `htpasswd` 가 아니라 **`rhbk`** 를 클릭합니다.
+
image::rhbk-mfa-login-select-rhbk.png[OpenShift 로그인 화면 — htpasswd 와 rhbk 중 rhbk 를 빨간 상자로 표시, link=self, window=blank, width=70%]
+
`rhbk` 는 Keycloak의 `redpay` realm으로 인증을 넘기는 Identity Provider입니다.
여기서 로그인하면 OpenShift가 아니라 **Keycloak이 사용자를 확인**하고, 그 결과를 OpenShift에 알려 줍니다.
+
TIP: 목록 없이 이전 세션으로 바로 로그인된다면, OCP Console 탭 옆의 **새로 고침 버튼**(원형 화살표)을 클릭하십시오.
+
. **REDPAY** 로그인 화면(OpenShift console)으로 이동합니다. 아직 계정이 없으므로 로그인 폼 아래의 *New user?* **Register** 링크를 클릭합니다.
+
image::rhbk-mfa-register-link.png[REDPAY 로그인 화면 — 아래쪽 New user? Register 링크를 빨간 상자로 표시, link=self, window=blank, width=60%]
+
. 사용자 정보를 입력합니다. **모든 항목을 채워야 합니다.** 아래 예시 값을 그대로 복사해 붙여 넣으십시오.
+
[cols="1,2",options="header"]
|===
| 항목 | 입력 값

| *Username*
a|
[source,text]
----
redpay-ops
----

| *Password*
a|
[source,text]
----
RedPay2026!
----

| *Confirm password*
a|
[source,text]
----
RedPay2026!
----

| *Email*
a|
[source,text]
----
redpay-ops@example.com
----

| *First name*
a|
[source,text]
----
RedPay
----

| *Last name*
a|
[source,text]
----
Operator
----
|===
+
. 아래 화면처럼 모든 항목을 입력한 뒤 *Register* 를 클릭합니다.
+
image::rhbk-mfa-register-form.png[Register 화면 — 예시 값(redpay-ops, redpay-ops@example.com, RedPay, Operator)을 입력하고 Register 버튼을 누르는 화면, link=self, window=blank, width=50%]

== 4단계 — QR 코드로 OTP 등록

*Register* 를 눌러도 곧바로 로그인되지 않고 **Mobile Authenticator Setup** 화면이 나타납니다.
2단계에서 켠 *Set as default action* 이 동작한 것입니다.

화면에는 **QR 코드**와 함께 *One-time code*, *Device Name* 입력 칸이 있습니다.

image::rhbk-mfa-otp-setup.png[Mobile Authenticator Setup 화면 — 빨간 상자의 QR 코드를 OTP 앱으로 스캔 (예시 이미지의 QR 코드는 가림), link=self, window=blank, width=50%]

NOTE: 위 그림의 QR 코드는 예시라 일부러 가려 두었습니다. 여러분 화면에 표시되는 QR 코드를 스캔하십시오.
QR 코드에는 이 계정의 OTP 비밀 키가 들어 있으므로, 실제 환경에서는 다른 사람에게 보여 주거나 캡처해 공유하지 마십시오.

사전 준비에서 고른 방법에 따라 아래 A 또는 B 중 하나만 진행하십시오.

=== 방법 A — 스마트폰 앱으로 등록

.실습 절차
. 스마트폰에서 OTP 앱을 열고 계정을 추가합니다.
+
[cols="1,3",options="header"]
|===
| 앱 | 메뉴

| Google Authenticator
| 오른쪽 아래 *+* → *QR 코드 스캔*

| Microsoft Authenticator
| 오른쪽 위 *+* → *기타 계정(Google, Facebook 등)* → QR 코드 스캔

| FreeOTP
| 위쪽 QR 코드 아이콘
|===
+
// 스마트폰 캡처 자리 — 파일을 content/modules/ROOT/images/ 에 넣고 아래 주석을 해제하십시오.
// image::rhbk-mfa-phone-01-add.png[OTP 앱에서 계정 추가 → QR 코드 스캔을 선택하는 화면, width=280]
+
. 카메라로 컴퓨터 화면의 **QR 코드**를 스캔합니다.
+
앱에 `RedPay: <사용자 이름>` 항목과 함께 **6자리 숫자**가 나타납니다. 이 숫자는 30초마다 바뀝니다.
+
image::rhbk-mfa-phone-02-code.png[Google Authenticator 앱에 RedPay: red 항목과 6자리 숫자가 표시된 화면, link=self, window=blank, width=60%]
+
TIP: 카메라로 스캔이 잘 되지 않으면 화면의 *Unable to scan?* 을 클릭하십시오. 앱에서 *설정 키 입력* (Google) 또는 *코드를 수동으로 입력* 을 골라 표시된 키 문자열을 입력하면 됩니다.

=== 방법 B — Chrome 확장 프로그램으로 등록

.실습 절차
. QR 코드가 보이는 상태에서, 도구 모음의 *Authenticator* 아이콘을 클릭합니다.
. 확장 프로그램 창 **오른쪽 위의 스캔 아이콘**(네모 안의 QR 모양)을 클릭합니다.
. 화면이 어두워지면 마우스로 **QR 코드 전체를 덮도록 사각형을 드래그**합니다.
. 확장 프로그램 창에 `RedPay` 항목과 **6자리 숫자**가 나타납니다. 오른쪽 아래 원은 숫자가 바뀌기까지 남은 시간입니다.
. 숫자를 클릭하면 클립보드에 복사됩니다.
+
[TIP]
====
스캔이 실패하면(예: Showroom 화면 안의 작은 탭이라 QR 코드가 잘리는 경우) 직접 입력하십시오.

. Keycloak 화면에서 *Unable to scan?* 을 클릭해 키 문자열을 복사합니다.
. *Authenticator* 창 오른쪽 위의 **연필 아이콘** → **+** → *Manual Entry* 를 선택합니다.
. *Issuer* 에 `RedPay`, *Secret* 에 복사한 키 문자열을 붙여 넣고 *Ok* 를 클릭합니다.

또는 OCP Console을 **새 브라우저 탭**으로 열어 QR 코드를 크게 띄운 뒤 다시 스캔해 보십시오.
====

=== 코드 입력 (A·B 공통)

.실습 절차
. 앱(또는 확장 프로그램)에 표시된 6자리 숫자를 *One-time code* 칸에 입력합니다.
. *Device Name* 에 기기를 구분할 이름을 입력합니다(예: `my-phone`, `chrome`). 선택 사항입니다.
. *Submit* 을 클릭합니다.
+
[NOTE]
====
`Invalid authenticator code` 오류가 나오면 숫자가 바뀐 직후의 **새 값**을 입력해 다시 시도하십시오.
계속 실패한다면 스마트폰(또는 PC)의 시간 설정이 **자동**으로 되어 있는지 확인하십시오. TOTP는 시각을 기준으로 계산됩니다.
====
+
. OpenShift 콘솔로 돌아오고, 오른쪽 위에 방금 등록한 사용자 이름이 표시됩니다.

== 5단계 — 관리 콘솔에서 결과 확인 (선택)

.실습 절차
. Keycloak 관리 콘솔(`redpay` realm)에서 왼쪽 메뉴의 *Users* 를 클릭합니다.
. 3단계에서 만든 사용자를 클릭하고 *Credentials* 탭을 엽니다.
. `password` 와 함께 **`otp`** 자격 증명이 등록되어 있는지 확인합니다. *Device Name* 에 입력한 이름도 보입니다.
+
TIP: 사용자가 스마트폰을 잃어버렸다면 관리자는 이 화면에서 `otp` 자격 증명을 **삭제**하면 됩니다. 사용자는 다음 로그인 때 새 기기로 OTP를 다시 등록합니다.

== 관리자 계정으로 돌아가기

다음 모듈부터는 클러스터 관리자 권한이 필요합니다.

.실습 절차
. **OCP Console** 탭에서 *Log out* 한 뒤, 관리자 계정의 Identity Provider(예: `htpasswd`)를 선택해 아래 자격 증명으로 로그인합니다.
+
[cols="1,1"]
|===
| *사용자 이름:* | {openshift_cluster_admin_username}
| *비밀번호:* | {openshift_cluster_admin_password}
|===
+
. 터미널은 처음부터 관리자로 연결되어 있습니다. 확인만 해 둡니다:
+
[source,bash,role="execute"]
----
oc whoami
----

== 학습 내용 요약

* **비밀번호는 "아는 것" 하나뿐입니다.** 아무리 복잡해도 유출되면 공격자와 사용자를 구별할 수 없습니다.
* **MFA는 서로 다른 종류의 증거를 요구합니다.** 비밀번호(아는 것) + OTP 앱(가진 것).
* *Configure OTP* 의 **Enabled** 는 "쓸 수 있다", **Set as default action** 은 "반드시 쓴다"입니다. 기능을 갖고 있는 것과 적용한 것은 다릅니다.
* TOTP는 QR 코드로 한 번 공유한 비밀 키와 현재 시각으로 계산되며, 30초마다 바뀝니다.
* OpenShift는 OIDC로 Keycloak에 인증을 맡기므로, **Keycloak에서 켠 MFA가 OpenShift 로그인에 그대로 적용**됩니다. OpenShift 쪽에서 따로 바꿀 설정은 없습니다.

== 다음 단계

1단계 공격은 막았습니다. 이제 유출된 비밀번호만으로는 운영자 계정에 들어올 수 없습니다.

하지만 RedPay 사고에서 피해를 회원 DB까지 넓힌 것은 **"내부에서 온 요청이면 믿는다"** 는 가정이었습니다.
공격자가 다른 경로로 한 번이라도 내부에 들어오면, 그 가정은 또다시 무너집니다.

xref:16-ztwim.adoc[다음 모듈]에서 2단계 공격 — 내부 요청을 무조건 신뢰한 문제 — 을 다룹니다.
