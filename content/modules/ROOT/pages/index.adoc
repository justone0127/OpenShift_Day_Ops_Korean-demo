== 시작하기

여러분에게는 **전용 계정과 전용 실습 네임스페이스**가 배정되어 있습니다.
실습은 반드시 이 계정으로 진행해야 합니다.

[IMPORTANT]
.먼저 로그인 계정을 확인하십시오
====
터미널이 **관리자 계정으로 열려 있을 수 있습니다.** 그대로 진행하면 여러분의 것이 아닌
자원을 건드리게 되므로, 시작 전에 반드시 확인하십시오.
====

NOTE: API 주소는 비워 두셔도 됩니다. 비워 두면 명령 실행 시 `oc whoami --show-server` 로
현재 클러스터 주소를 자동으로 가져옵니다.

.실습 절차
. 위에 값을 입력하고 *적용* 을 누른 뒤, 아래 명령을 실행하십시오:
+
[source,bash,role="execute"]
----
export LAB_USER=__USER__
export API=__API__
export KUBECONFIG=/tmp/kubeconfig-$LAB_USER
oc login -u $LAB_USER -p __PASSWORD__ $API --insecure-skip-tls-verify=true
echo "로그인 계정: $(oc whoami)   |   클러스터: $API"
----
+
마지막 줄에 본인 계정이 표시되면 성공입니다.
+
NOTE: `__USER__` 나 `__PASSWORD__` 가 그대로 보이면 위 입력란에 값을 넣고 *적용* 을 누르십시오.
+
NOTE: `KUBECONFIG` 를 세션 전용 파일로 두는 이유는, 터미널 서버를 여러 참가자가 공유할 때
기본 설정 파일에 서로의 로그인이 덮어써지는 것을 막기 위해서입니다.
+
. 계정과 배정된 네임스페이스를 확인합니다:
+
[source,bash,role="execute"]
----
oc whoami
oc get projects
----
+
본인 계정과 함께 다음 세 개의 프로젝트가 보이면 준비가 된 것입니다
(`user1` 자리에는 본인 계정이 표시됩니다):
+
[source,text]
----
user1-narupay
user1-postgresql-spiffe
user1-postgresql-spiffe-client
----
+
NOTE: 다른 참가자의 네임스페이스나 클러스터 관리용 네임스페이스는 보이지 않는 것이 정상입니다.
  노드나 클러스터 설정을 조회하는 명령도 권한 밖이라 `Forbidden` 이 납니다.
+
. 실습 워크로드가 준비되어 있는지 확인합니다:
+
[source,bash,role="execute"]
----
oc get deployment -n $LAB_USER-narupay
----
+
`payment-api`, `payment-api-secure`, `legacy-secret-app` 세 개가 보이면 준비가 완료되었습니다.

[WARNING]
.명령이 갑자기 실패하면 이 절차를 다시 실행하십시오
====
터미널 연결이 끊기면 위에서 설정한 `LAB_USER` 와 `KUBECONFIG` 가 사라집니다.
`Forbidden` 이나 `namespace not found` 오류가 나면 1번 단계 명령을 다시 실행하십시오.
입력한 계정은 브라우저에 저장되어 있으므로 다시 입력할 필요는 없습니다.
====

== 워크숍 소개

클러스터는 잘 돌아갑니다. 그런데 다음 질문에는 바로 답하기 어렵습니다:

- 6개월 전 CI 스캔을 통과한 이미지가, **지금도** 안전합니까?
- `Secret` 에 넣어 둔 비밀번호는 실제로 얼마나 보호되고 있습니까?
- 내부망에서 들어온 요청은 **무엇을 근거로** 신뢰합니까?

본 워크숍은 하나의 침해사고를 따라가며 이 세 질문에 차례로 답합니다.
공격이 어떻게 세 단계를 통과했는지 보고, 각 단계를 막는 방어선을
직접 세워 보게 됩니다.

실습은 관찰과 판단 중심입니다. 긴 YAML을 붙여넣을 일은 없습니다.

=== 워크숍 인터페이스

본 워크숍은 다음과 같은 영역으로 나뉜 분할 화면 인터페이스로 제공됩니다:

* **왼쪽 패널** - 가이드 문서 (현재 읽고 있는 화면)
* **오른쪽 패널** - 클러스터 도구들이 탭 형태로 포함된 작업 영역
* **크기 조절 드래그 바** - 패널 사이의 경계를 드래그하여 화면 크기를 조절할 수 있습니다.

image::showroom-tabs.png[OCP Console, Terminal, RHACS, ArgoCD, Developer Hub 탭을 보여주는 Showroom 인터페이스, link=self, window=blank]
[cols="1,3"]
|===
|Tab |What it is

|**OCP Console**
|OpenShift 웹 콘솔 - 클러스터 관리, 모니터링 대시보드 및 트러블슈팅을 수행합니다.

|**Terminal**
|클러스터에 사전 연결된 웹 기반 터미널입니다. 로컬 환경 설정 없이 `oc` 명령어를 직접 실행할 수 있습니다.

|**RHACS**
|Red Hat Advanced Cluster Security - 취약점 스캔, 컴플라이언스 및 런타임 보안을 제공합니다.

|**ArgoCD**
|OpenShift GitOps - GitOps 원칙을 사용한 지속적 배포(CD)를 지원합니다.

|**Developer Hub**
|Red Hat Developer Hub - 소프트웨어 카탈로그와 셀프 서비스 템플릿을 제공하는 개발자 포털입니다.
|===

NOTE: 이번 세션에서는 **OCP Console**, **Terminal**, **RHACS** 세 개의 탭을 사용합니다.
나머지 탭은 다른 트랙에서 쓰이며 이번 실습에는 필요하지 않습니다.

TIP: 음영 처리된 명령어 블록은 **클릭이 가능**하며, 클릭 시 자동으로 **Terminal (터미널)** 탭으로 전환되어 명령어가 실행됩니다.

=== 모듈 구성

이번 세션은 **하나의 침해사고 시나리오로 이어지는 세 개의 모듈**로 구성됩니다.
각 모듈이 공격 단계 하나씩을 막습니다. 왼쪽 내비게이션 순서대로 진행하십시오.

[cols="1,2,2",options="header"]
|===
| 모듈 | 막는 공격 단계 | 무엇을 하는가

| **인트로 — 침해사고**
| —
| 사건의 전말과 3단계 공격 경로를 확인합니다. 워밍업 퀴즈 3문항.

| **모듈 1 — RHACS**
| 1단계: 취약한 이미지와 과도한 권한
| 취약/강화 워크로드를 콘솔에서 비교하고, 정책을 탐지에서 **차단**으로 전환해
  취약한 배포가 실제로 거부되는 것을 확인합니다.

| **모듈 2 — ZTWIM**
| 3단계: 네트워크 위치 기반 신뢰
| 워크로드에 발급된 암호학적 신원(SVID)을 확인하고, 비밀번호 없이 연결되는 것과
  신원 없는 접속이 거부되는 것을 봅니다.

| **모듈 3 — Secrets Management**
| 2단계: 훔칠 수 있는 정적 비밀번호
| `Secret` 의 실제 보호 수준을 직접 측정하고, 전용 저장소가 무엇을 바꾸는지 확인합니다.
|===

[NOTE]
====
모듈 2(ZTWIM)가 공격 3단계를, 모듈 3(Secrets)이 2단계를 다룹니다. 순서가 바뀐 이유는
**신원으로 대체할 수 있는 것을 먼저 없애고, 그래도 남는 비밀을 마지막에 다루기** 위해서입니다.
====

=== 1단계: 어드민 콘솔 접속

OpenShift 웹 콘솔은 클러스터 전체에 대한 통합된 뷰를 제공합니다.

image::ocp-console-overview.png[OpenShift Administrator 콘솔 개요, link=self, window=blank]
콘솔에 접속하는 방법은 두 가지가 있습니다:

* **OCP Console 탭** - 본 워크숍 화면 상단의 **OCP Console** 탭을 클릭하십시오. 콘솔이 워크숍 인터페이스에 직접 내장되어 있어 창을 전환하지 않고도 편리하게 실습을 따라 할 수 있습니다.
* **별도의 브라우저 탭** - 전체 화면으로 실습하기를 원하신다면, 다음 URL을 클릭하여 새 브라우저 탭에서 콘솔을 열 수 있습니다:
{openshift_cluster_console_url}[window=blank]

NOTE: URL을 새 탭에서 열려면 `ctrl + 클릭` 하십시오.

TIP: 인증 오류가 발생하는 경우 **Try Again (다시 시도)**을 클릭하거나 상단 탭을 새로고침하십시오.

여러분의 로그인 자격 증명입니다. 콘솔에서도 **본인 계정으로** 로그인하십시오:

[cols="1,1"]
|===
| *사용자 이름:* | 배정받은 본인 계정 (예: `user1`)
| *비밀번호:* | 진행자가 안내한 비밀번호
|===

NOTE: 관리자 계정으로 로그인하면 다른 참가자의 자원까지 보이게 됩니다. 본인 계정을 사용하십시오.

=== 2단계: 대시보드 개요

**Home (홈) → Overview (개요)** 메뉴에서 **Overview (개요)** 대시보드를 확인할 수 있습니다.

image::ocp-dashboard-overview.png[OpenShift Administrator 대시보드 개요, link=self, window=blank]
**확인해야 할 주요 영역:**

1. **Cluster Status (클러스터 상태)** - 전반적인 헬스 상태를 한눈에 볼 수 있습니다.
2. **Cluster Utilization (클러스터 사용량)** - CPU, 메모리, 스토리지 메트릭을 보여줍니다.
3. **Cluster Inventory (클러스터 인벤토리)** - 노드 수, Pod 수 등을 표시합니다.
4. **Activity (활동)** - 최근 이벤트 및 경고(alert)를 확인할 수 있습니다.

이 하나의 대시보드에서 클러스터 상태, 사용량, 인벤토리, 최근 이벤트를 별도의 설정 없이 모두 한눈에 확인할 수 있습니다.
