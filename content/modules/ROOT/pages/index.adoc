== Getting started

Each of you has a **dedicated OpenShift cluster**, and the terminal is already
connected with cluster-admin privileges. No additional login is required.

.Procedure
. Confirm that you are connected to the cluster:
+
[source,bash,role="execute"]
----
oc whoami
----
+
If the admin account is displayed, you are good to go.
+
. Confirm that the lab environment is ready:
+
[source,bash,subs="+attributes",role="execute"]
----
oc get pod keycloak-0 -n rhbk
oc get deployment -n {redpay_ns}
----
+
The environment is ready when you see the following:
+
[source,text]
----
keycloak-0           # Red Hat build of Keycloak — Module 1 (Running)
payment-api          # Vulnerable version — Module 3
payment-api-secure   # Hardened version — Module 3
----
+
NOTE: If you do not see these items, or the `rhbk` or `{redpay_ns}` namespace does not exist,
  please let the facilitator know. The facilitator is responsible for preparing the lab environment.

== About this workshop

Your cluster is running fine. But these questions are hard to answer right away:

- Could someone log in to an operator account knowing nothing but a single password?
- On **what basis** do you trust requests coming from inside your network?
- Is the image that passed a CI scan six months ago **still** safe today?

This workshop follows a single security breach and answers these three questions in turn.
You will see how the attack got through three stages, and you will apply the security
control that stops each stage yourself.

The labs focus on observation and judgment. You will not need to paste long YAML files.

=== Modules

This session consists of **three modules that follow a single breach scenario**.
Each module stops one stage of the attack. Work through them in the order shown in the left navigation.

[cols="1,2,2",options="header"]
|===
| Module | Attack stage it stops | What you do

| **Intro — The breach**
| —
| Review what happened and the three-stage attack path. Four warm-up quiz questions.

| **Module 1 — Red Hat build of Keycloak**
| Stage 1: An operator account breached with a single password
| **Enforce** the OTP feature that was already available **for every user**, register a QR code
  as a new user, and log in to OpenShift with an OTP token.

| **Module 2 — ZTWIM**
| Stage 2: Unconditional trust of internal requests
| Inspect the cryptographic identity (SVID) issued to a workload, and see a passwordless connection
  succeed while a connection without an identity is rejected.

| **Module 3 — RHACS**
| Stage 3: A `latest` image carrying a library with an RCE vulnerability
| Compare the vulnerable and hardened workloads in the console, switch a policy from detection
  to **enforcement**, and confirm that the vulnerable deployment is actually rejected.
|===
