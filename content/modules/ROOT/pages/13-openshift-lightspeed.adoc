= OpenShift Lightspeed
:page-toclevels: 1

== 모듈 개요

**소요 시간:** 15-20분 +
**형식:** Hands-on AI assistant 탐색 +
**대상:** Platform Engineers, Developers, Operations Teams

include::partial$console-access.adoc[]

OpenShift Lightspeed (OLS)는 OpenShift web console에 통합된 AI 기반 assistant로, Large Language Models (LLMs)와 공식 OpenShift 문서를 Retrieval-Augmented Generation (RAG)을 통해 결합하여 administrator와 developer가 다음과 같은 작업을 수행할 수 있도록 지원합니다:

* OpenShift 개념 및 아키텍처 이해
* configuration에 대한 가이드 제공
* YAML 생성 지원
* cluster 문제 troubleshooting

이 모듈에서는 OpenShift Lightspeed를 configuration하고, 이를 사용하여 OpenShift 개념을 이해하고, cluster resource에서 정보를 수집하며, 손상된 workload 등을 troubleshooting하는 방법을 실습합니다.

=== 사전 요구 사항

OpenShift Lightspeed Operator가 cluster에 사전 설치되어 있습니다. 하지만 완전히 작동하려면 OpenShift Lightspeed를 LLM provider에 연결해야 합니다. 이 모듈에서는 이 연결을 활성화하는 데 필요한 configuration도 생성해 봅니다.

=== OLSConfig 생성

operator가 설치되었지만 LLM provider에 연결하기 위한 configuration이 필요합니다. OpenShift Lightspeed는 퍼블릭 클라우드 서비스(WatsonX, Azure OpenAI, OpenAI) 및 온프레미스 솔루션(Red Hat OpenShift AI, RHEL AI)을 포함한 다양한 model provider를 지원합니다. 본 워크숍에서는 Azure OpenAI credential이 secret으로 사전 configuration되어 있습니다.

credential secret이 존재하는지 확인하십시오:

[source,bash,role=execute]
----
oc get secret azure-api-keys -n openshift-lightspeed
----

이제 OpenShift Lightspeed를 활성화하기 위해 OLSConfig를 생성하십시오:

[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -f - <<EOF
apiVersion: ols.openshift.io/v1alpha1
kind: OLSConfig
metadata:
  name: cluster
spec:
  llm:
    providers:
      - name: Azure
        type: azure_openai
        url: 'https://llm-gpt4-lightspeed.openai.azure.com/'
        deploymentName: gpt-4
        credentialsSecretRef:
          name: azure-api-keys
        models:
          - name: gpt-4
  ols:
    defaultModel: gpt-4
    defaultProvider: Azure
    logLevel: DEBUG
    introspectionEnabled: true
EOF
----

주요 configuration parameter는 다음과 같습니다:

* `spec.llm.providers` - 사용할 LLM provider를 정의합니다:
** `type` - provider 유형 (예: `azure_openai`, `watsonx`, `rhoai_vllm` 등)
** `url` - LLM 서비스의 endpoint URL
** `credentialsSecretRef` - API credential을 포함하는 secret을 참조합니다
** `models` - 해당 provider에서 사용할 model 이름
* `spec.ols.defaultModel` - query에 대해 기본적으로 사용할 model을 지정합니다
* `spec.ols.defaultProvider` - 여러 개의 provider가 configuration되어 있을 때 기본 provider를 설정합니다
* `spec.ols.introspectionEnabled` - `true`로 설정하면, OpenShift Lightspeed가 사용자에게 context-aware(문맥 인식) 응답을 제공하기 위해 cluster resource를 query할 수 있는 MCP server를 자동으로 배포합니다 (OpenShift 4.20의 Technology Preview 기능)

=== OpenShift Lightspeed 초기화 대기

TLS 인증서가 생성되고 container image가 풀(pull)되는 동안 Lightspeed pod가 시작되는 데 3-5분 정도 소요됩니다. 다음 명령을 실행하여 모든 구성 요소가 준비될 때까지 대기하십시오:

[source,bash,role="execute"]
----
echo "Waiting for Lightspeed to start (this takes 3-5 minutes)..."
ELAPSED=0
until oc get pods -n openshift-lightspeed -l app.kubernetes.io/component=application-server --no-headers 2>/dev/null | grep -q "3/3.*Running"; do
  sleep 10; ELAPSED=$((ELAPSED+10))
  [ $ELAPSED -ge 600 ] && echo "ERROR: Timed out after 10 minutes" && break
done
echo "Lightspeed is ready"
oc get pods -n openshift-lightspeed
----

모든 pod가 `Running` 상태여야 합니다:

----
NAME                                                     READY   STATUS    RESTARTS        AGE
lightspeed-app-server-xxxxx                              3/3     Running   0               3m
lightspeed-console-plugin-xxxxx                          1/1     Running   0               3m
lightspeed-operator-controller-manager-xxxxx              1/1     Running   0               83m
lightspeed-postgres-server-xxxxx                         1/1     Running   1               3m
----

NOTE: postgres pod의 restart 횟수가 1로 표시될 수 있으나, 이는 초기 시작 시 발생하는 정상적인 현상입니다.

OLSConfig 상태를 확인하십시오:

[source,bash,role=execute]
----
oc get olsconfig cluster -o jsonpath='{.status.conditions}' | jq .
----

모든 condition의 `"status"`가 `"True"`이고, `"message"`가 `"Ready"`로 표시되어야 합니다.

== Lightspeed 사용

=== Web Console에서 OpenShift Lightspeed 접속

Lightspeed 배포 과정에서 console에서 로그아웃되었을 수 있습니다. 로그아웃된 경우, 다음 정보를 사용하여 다시 로그인하십시오:

* Username (사용자 이름): `{openshift_cluster_admin_username}`
* Password (비밀번호): `{openshift_cluster_admin_password}`

TIP: Lightspeed를 사용할 때 인증 오류가 발생하는 경우, **OCP Console** 탭을 새로고침한 후 다시 시도하십시오.

OLSConfig가 준비되면 우측 하단 모서리에 있는 OpenShift Lightspeed 채팅 버튼이 활성화됩니다:

=== 기본 질문

OpenShift Lightspeed를 사용하면 자연어를 통해 OpenShift에 대해 소통하고 질문을 던질 수 있습니다. OpenShift에 특화된 지식을 제공하므로, 이 플랫폼의 개념과 resource를 탐색하고 이해하는 데 특히 유용합니다.

NOTE: Lightspeed 응답은 AI model에 의해 생성되므로, 표시되는 출력 결과가 본 예시와 다를 수 있습니다.

예를 들어, 다음과 같은 질문으로 시작할 수 있습니다:

[quote]
What's the difference between a Deployment and a StatefulSet?

OpenShift Lightspeed는 vector database에서 가장 관련성이 높은 문서 섹션을 검색합니다. 그런 다음 이 정보는 query와 함께 model로 전달되어 정확한 응답을 제공할 수 있도록 지원합니다.

OpenShift Lightspeed는 Deployment 및 StatefulSet resource가 각각 무엇인지 설명하고 이 둘을 비교하는 응답을 제공할 것입니다. 응답 맨 아래로 스크롤하면 OpenShift Lightspeed가 가장 관련성이 높은 공식 문서 링크를 표시하여, 해당 섹션에 신속하게 액세스하고 더 깊이 알아볼 수 있도록 돕습니다:

== 제공 기능

=== YAML 생성 지원

OpenShift Lightspeed는 진행 중인 대화의 context를 유지하므로, 이전 응답을 구체화하거나 확장하기 위한 후속 질문을 던질 수 있습니다.

예를 들어, Deployment가 무엇인지 확인했으므로, OpenShift Lightspeed에게 Deployment를 생성해 달라고 요청해 보겠습니다:

=== 클러스터 상호작용 및 트러블슈팅

워크숍 환경 구성의 일환으로 의도적인 문제가 있는 데모 pod가 사전 배포되어 있습니다. OpenShift Lightspeed를 사용하여 이를 진단해 보겠습니다.

먼저, 문제가 발생한 pod를 확인하십시오:

[source,bash,role=execute]
----
oc get pods -n lightspeed-demo
----

`Pending` 상태로 멈춰 있는 pod를 확인할 수 있습니다:

[source,bash,role=execute]
----
oc describe pod broken-pod -n lightspeed-demo
----

커맨드 라인을 통해 조회한 것과 동일한 정보를 OpenShift Lightspeed에도 요청할 수 있습니다. 앞서 OLSConfig를 configuration할 때 `introspectionEnabled`를 `true`로 설정했던 것을 기억하실 것입니다. 이는 OpenShift Lightspeed가 cluster 내부의 resource에 액세스할 수 있음을 의미합니다.

OpenShift Lightspeed 인터페이스에서, 대화를 초기화하기 위해 채팅 패널의 우측 상단(왼쪽)에 있는 **휴지통 아이콘**을 클릭하십시오. 이제 다음과 같이 질문할 수 있습니다:

[quote]
Show me the pods in the lightspeed-demo namespace

model은 이 정보를 가져오기 위해 MCP server가 제공하는 tool 중 하나인 `pods_list_in_namespace`를 사용했을 것입니다. tool을 클릭하면 질문에 답변하는 데 사용된 tool output을 볼 수 있습니다.

image::ols-tool-output.png[OpenShift Lightspeed MCP tool output, link=self, window=blank]
이제 OpenShift Lightspeed의 도움을 받아 문제를 진단해 보겠습니다. OpenShift Lightspeed로 troubleshooting을 진행할 때, 첨부(attachment) 기능을 사용하여 분석 대상인 다양한 resource와 configuration을 model로 전달함으로써 문제를 식별하고 해결할 수 있습니다.

OpenShift web console에서 *Workloads (워크로드)* → *Pods (포드)* 메뉴로 이동하고, `lightspeed-demo` namespace에 있는지 확인하십시오. 이전에 OpenShift Lightspeed가 나열했던 pod를 확인할 수 있습니다. `broken-pod`를 클릭하여 resource 상세 정보를 확인하십시오.

이제 채팅 창의 텍스트 입력창 옆에 있는 *클립* 아이콘을 클릭하면, 다양한 구성 요소를 첨부할 수 있는 메뉴가 표시됩니다. *Full YAML file*을 선택하십시오:

image::ols-attachments.png[OpenShift Lightspeed attachments menu, link=self, window=blank]
첨부한 후, 다음과 같이 질문해 보십시오:

[quote]
What's wrong in this pod?

OpenShift Lightspeed는 pod 사양(specification)을 분석하여 문제점(이 경우 잘못된 node selector)을 식별할 것입니다. 추가로, 문제 해결에 도움이 되는 솔루션을 제안해 줍니다.

=== 컨테이너를 넘어선 OpenShift Lightspeed

이 모듈 전체에서 OpenShift Lightspeed가 Pod, Deployment, Route, Service 등과 같은 container 기반 workload를 어떻게 지원할 수 있는지 살펴보았습니다. 그러나 OpenShift 플랫폼은 container 환경을 넘어 더욱 광범위하게 확장됩니다.

OpenShift Virtualization을 사용하면 container와 동일한 플랫폼에서 virtual machine(VM)을 실행할 수 있습니다. OpenShift의 VM은 custom resource로 관리되므로, OpenShift Lightspeed를 통해 매우 효율적으로 지원을 받을 수 있습니다. VM 네트워킹 개념의 이해부터 시작하여 기동 시의 문제 troubleshooting, virtual machine configuration 생성에 이르기까지 OpenShift Lightspeed를 통해 도움을 얻을 수 있습니다.

Red Hat Advanced Cluster Management (ACM)도 마찬가지입니다. 다중 cluster 환경에서 작업할 때 ManagedCluster 또는 ManagedClusterInfo와 같은 resource는 동일한 custom resource 패턴을 따르므로, OpenShift Lightspeed를 통해 query를 수행하고 가이드를 받을 수 있습니다.

이 모듈은 여기서 마무리되지만, OpenShift Lightspeed operator는 남은 워크숍 진행 시간 동안 활성화 상태로 유지됩니다. 개념을 명확히 하고 싶거나, resource 정의를 생성하거나, 가상화 및 다중 cluster 작업에 관한 가이드가 필요한 경우, 향후 모듈을 진행하면서 필요할 때 언제든지 계속 사용해 보십시오.

== 정리 및 요약

데모 namespace를 정리하십시오:

[source,bash,role="execute"]
----
oc delete namespace lightspeed-demo --ignore-not-found --wait=false
echo "Cleanup complete - you can continue to the next module"
----

NOTE: OLSConfig와 Lightspeed 서비스는 계속 실행 중입니다. 이후 모듈에서 Lightspeed를 계속 사용하려면 그대로 유지하십시오. 완전히 제거하려는 경우 다음 명령을 실행하십시오:

[source,bash,role="execute"]
----
oc delete olsconfig cluster
----

OpenShift Lightspeed는 console에서 직접 AI가 지원하는 운영 편의성을 제공합니다. 자연어 소통을 가능하게 함으로써, administrator와 developer가 OpenShift에 대한 초기 학습 장벽을 신속하게 극복할 수 있도록 도우며, 일반적인 문제의 해결 시간(time-to-resolution)을 줄여 생산성을 높여 줍니다.
