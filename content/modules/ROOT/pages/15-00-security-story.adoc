== 06:00 AM — 공격 경로 3단계

보안팀이 밤새 로그를 뒤진 결과, 공격 경로가 드러났습니다.

=== 1단계 — "그냥 최신 버전 쓰면 되죠?"

6개월 전, 급하게 배포된 결제 API 이미지입니다.

[source,yaml]
----
image: payment-api:latest   # ← 태그가 latest
env:
  - name: DB_PASSWORD       # ← 자격 증명이 평문 환경변수로
    value: "NuriPay2024!@#"
# resources 없음           ← 노드 자원을 전부 소진시킬 수 있음
# securityContext 없음     ← 불필요한 권한 유지
----

`latest` 태그가 가리키던 베이스 이미지에는 원격 코드 실행(RCE) 취약점이 있었습니다.
아무도 몰랐습니다. **배포 이후로는 아무도 스캔하지 않았으니까요.**

[TIP]
====
*"이미지 스캔은 CI에서 하고 있었는데요?"* +
→ CI를 통과한 **뒤에** 배포된 이미지는 누가 봅니까? +
→ 어제는 안전했던 이미지에 오늘 CVE가 공개되면요?
====

=== 2단계 — "Secret에 넣어놨는데요?"

셸을 얻은 공격자가 가장 먼저 한 일입니다.

[source,bash]
----
$ env | grep -i pass
DB_PASSWORD=NuriPay2024!@#

$ oc get secret payment-db-creds -o jsonpath='{.data.password}'
TnVyaVBheTIwMjQhQCM=

$ echo "TnVyaVBheTIwMjQhQCM=" | base64 -d
NuriPay2024!@#
----

**Kubernetes Secret의 `data` 값은 암호화가 아니라 Base64 인코딩입니다.**
누구나 되돌릴 수 있습니다. 이것은 "숨김"이지 "보호"가 아닙니다.

더 나쁜 건 — 그 비밀번호는 3년째 한 번도 바뀌지 않았다는 점입니다.
바꾸려면 참조하는 모든 워크로드를 동시에 재시작해야 했으니까요.

=== 3단계 — "내부망이니까 괜찮아요"

DB 비밀번호를 얻은 공격자는 이제 **정상 사용자**입니다.

누리페이의 내부 서비스들은 서로를 이렇게 인증했습니다.

[source,text]
----
"10.128.0.0/14 대역에서 온 요청이면 = 우리 서비스"
----

공격자는 이미 그 대역 안에 있습니다.
결제 서비스 → 정산 서비스 → 회원 DB, 전부 통과했습니다.

**네트워크 위치를 신원으로 착각한 것**이 마지막 방어선을 무너뜨렸습니다.

[TIP]
====
*"방화벽이 있잖아요?"* +
→ 방화벽은 "어디서 왔는가"를 봅니다. 공격자는 이미 "안"에 있습니다.
====

== 여러분의 임무 — 3개의 방어선

경영진이 묻습니다. **"다시는 이런 일이 없게 하려면, 무엇을 해야 합니까?"**

이어지는 세 모듈이 각각의 답입니다.

[cols="1,2,3",options="header"]
|===
| 모듈 | 막는 공격 단계 | 핵심 아이디어

| *15 — RHACS*
| 1단계: 취약한 이미지와 과도한 권한
| 취약한 컨테이너가 **애초에 뜨지 못하게** 만든다. 배포 시점에 정책 위반을 차단하고, 실행 중인 컨테이너의 행위를 감시한다.

| *16 — Secrets Management*
| 2단계: 훔칠 수 있는 정적 비밀번호
| 비밀을 Secret에 두지 않는다. 전용 저장소가 보관하고, 필요한 순간에만 짧은 수명으로 발급한다.

| *17 — ZTWIM*
| 3단계: 네트워크 위치 기반 신뢰
| **훔칠 비밀번호 자체를 만들지 않는다.** 워크로드가 암호학적 신원(SVID)을 갖고, IP가 아니라 신원으로 신뢰한다.
|===

== 실습 환경 준비

이 트랙의 실습 워크로드는 **사전 배포 스크립트로 한 번에 준비**됩니다.
가이드를 진행하면서 긴 YAML을 복사·붙여넣기 할 필요가 없습니다.

[IMPORTANT]
====
진행자가 이미 환경을 준비해 둔 경우 이 절을 건너뛰고 바로 아래 워밍업 퀴즈로 이동하십시오.
확실하지 않다면 `status` 명령으로 먼저 확인할 수 있습니다.
====

.실습 절차
. bastion에서 워크샵 리포지토리를 받고 사전 배포 스크립트를 실행합니다:
+
[source,bash,subs="+macros,+attributes",role=execute]
----
cd ~/
git clone {workshop_repo_url} 2>/dev/null || git -C ~/{workshop_repo_dir} pull
cd ~/{workshop_repo_dir}/setup-scripts/security-track-scripts
./setup-security-track.sh all
----
+
[NOTE]
====
`all` 은 15/16/17번 모듈에 필요한 모든 것을 준비하며 약 8~12분이 걸립니다.
대부분은 Vault와 SPIRE 설치를 기다리는 시간입니다.

특정 모듈만 준비하려면 `acs`, `vault`, `ztwim` 중 하나를 인자로 주십시오.
====
+
. 준비 상태를 확인합니다:
+
[source,bash,subs="+macros,+attributes",role=execute]
----
cd ~/{workshop_repo_dir}/setup-scripts/security-track-scripts
./setup-security-track.sh status
----
+
`nuripay` namespace에 `payment-api`, `payment-api-secure`, `legacy-secret-app` 세 개의 deployment가
보이면 준비가 끝난 것입니다.

=== Q0-1

누리페이의 CI 파이프라인에는 이미지 스캔이 있었습니다. 그런데도 뚫린 이유로 **가장 적절한** 것은?

[none]
* (A) 스캔 도구의 탐지율이 낮아서
* (B) 배포 이후에 공개된 CVE와, 클러스터에 실제로 떠 있는 것을 아무도 지속적으로 보지 않아서
* (C) 개발자가 스캔 결과를 무시해서
* (D) 이미지가 너무 커서 스캔이 타임아웃돼서

.정답 및 해설 보기
[%collapsible]
====
**정답: (B)**

CI 스캔은 **그 시점의 스냅샷**입니다. 통과한 순간 스캔의 임무는 끝나지만,
컨테이너는 그 뒤로 몇 달을 계속 돌아갑니다.

CVE는 매일 새로 공개됩니다. 어제 깨끗했던 이미지가 오늘 취약해집니다.
그래서 스캔은 파이프라인의 한 단계가 아니라 **클러스터에서 계속 돌아가는 상태 점검**이어야 합니다.
15번 모듈에서 RHACS가 바로 이 역할을 하는 것을 보게 됩니다.
====

=== Q0-2

`oc get secret`으로 나온 `data:` 값에 대해 **맞는** 설명은?

[none]
* (A) AES-256으로 암호화되어 있다
* (B) etcd에 저장될 때만 암호화되고 조회 시 복호화된다
* (C) Base64 인코딩이며, 별도 설정이 없으면 etcd에도 평문으로 저장된다
* (D) Kubernetes가 자동으로 키를 회전시킨다

.정답 및 해설 보기
[%collapsible]
====
**정답: (C)**

Base64는 인코딩이지 암호화가 아닙니다. 키도 없고, 누구나 되돌릴 수 있습니다.

etcd 저장 시 암호화(encryption at rest)는 **기본값이 아니라 별도로 켜야 하는 옵션**입니다.
그리고 설령 켜더라도, 컨테이너 안에서 `env`를 치면 값은 그대로 보입니다.
16번 모듈에서 직접 확인합니다.
====

=== Q0-3

"같은 네트워크 대역 = 믿을 수 있는 서비스"라는 가정의 가장 큰 문제는?

[none]
* (A) IP 대역이 부족해진다
* (B) 공격자가 한 번 내부에 들어오면 그 순간부터 모든 서비스가 그를 신뢰한다
* (C) 네트워크 성능이 느려진다
* (D) IPv6에서는 동작하지 않는다

.정답 및 해설 보기
[%collapsible]
====
**정답: (B)**

이것을 흔히 "M&M 보안"이라고 부릅니다. 껍질은 딱딱하지만 속은 말랑한 구조입니다.

경계 방어는 **한 번만 뚫리면 되는** 구조입니다. 침입 이후의 횡적 이동(lateral movement)을
막아 주는 것이 아무것도 없습니다. Zero Trust는 "내부"라는 개념 자체를 없애고,
**모든 연결이 매번 신원을 증명**하게 만듭니다. 17번 모듈의 주제입니다.
====
