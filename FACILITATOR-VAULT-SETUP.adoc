= 모듈 3 (Secrets Management) Vault 사전 구성 참고 문서
:toc: left
:toclevels: 3

핸즈온 가이드 담당자를 위한 문서입니다.
보안 트랙 전체 준비 절차는 link:FACILITATOR-SECURITY-TRACK.adoc[FACILITATOR-SECURITY-TRACK.adoc] 를 참고하시고,
이 문서는 **Vault 부분만** 자세히 다룹니다.

[IMPORTANT]
.왜 이 문서가 따로 있는가
====
현재 배포되는 실습 환경에는 다음이 **사전 설치되어 있습니다**:

* *RHACS* (Central + SecuredCluster) — 모듈 1
* *ZTWIM 오퍼레이터* — 모듈 2

하지만 **Vault 는 포함되어 있지 않습니다.**
모듈 3 을 진행하려면 담당자가 직접 설치·구성해야 합니다.

참가자 가이드에는 설치 절차가 없으므로, 준비되지 않은 상태로 세션을 시작하면
모듈 3 의 두 번째 실습(Vault UI 확인)에서 진행이 막힙니다.
====

== 한눈에 보기

[cols="1,3",options="header"]
|===
| 단계 | 명령

| 1. 트랙 전체 준비 (Vault 포함)
| `./setup-security-track.sh all`

| 1'. Vault 만 준비
| `./setup-security-track.sh vault`

| 2. 점검
| `./verify-vault.sh`

| 3. 문제 시 자동 복구 시도
| `./verify-vault.sh --fix`
|===

[NOTE]
====
`all` 은 Vault 설치·구성·시드를 **포함**합니다. 따로 `vault` 를 실행할 필요가 없습니다.

`all` 은 가이드 진행 순서(RHACS → ZTWIM → Secrets Management)대로 준비하고,
마지막에 모듈별 결과를 `[✓]` / `[✗]` 로 요약합니다.
하나라도 실패하면 **종료 코드 1** 을 반환하므로 프로비저닝 파이프라인에서 게이트로 쓸 수 있습니다.
====

실행 위치는 bastion 의 `setup-scripts/security-track-scripts/` 이며,
`cluster-admin` 으로 `oc login` 된 상태여야 합니다.

소요 시간은 약 **4~7분**입니다(대부분 Helm 차트 pull 과 pod 기동 대기).

== 무엇이 설치되는가

`setup-security-track.sh vault` 는 다음 순서로 동작합니다.

[cols="1,2,3",options="header"]
|===
| 순서 | 수행 주체 | 내용

| 1
| `setup-security-track.sh`
| `manifests/legacy-secret-app.yaml` 배포 — Kubernetes `Secret` 을 환경변수로 주입하는
  비교 대상 애플리케이션 (`narupay` namespace)

| 2
| `vault-config-scripts/install-vault.sh`
| Helm 이 없으면 자동 설치한 뒤, `hashicorp/vault` 차트로 `vault` namespace 에 Vault 배포.
  Route 도 함께 생성합니다.

| 3
| `vault-config-scripts/configure-vault-lab.sh`
| `read-policy` 생성, Kubernetes auth method 활성화 및 `vault-role` 구성

| 4
| `setup-security-track.sh`
| 실습용 secret 시드 — `secret/narupay/payment-db` 에 `username` / `password` 기록
|===

=== 설치 형상

[cols="1,2",options="header"]
|===
| 항목 | 값

| Namespace | `vault`
| Helm 릴리스 | `vault`
| 차트 | `hashicorp/vault` (repo `https://helm.releases.hashicorp.com`)
| values | `vault-config-scripts/vault-values-openshift-lab.yaml`
| 이미지 | `docker.io/hashicorp/vault:1.21.2` (OpenShift 의 short-name 재작성을 피하려고 전체 경로 사용)
| 실행 모드 | **dev mode** — 자동 unseal, root 토큰 `root`
| UI | 활성화, Route 로 노출 (edge TLS)
| Injector | 활성화 (`vault-k8s` 1.7.2)
| CSI provider | 비활성화
|===

[WARNING]
.dev mode 의 의미
====
Vault 가 **dev mode** 로 뜹니다. 학습 전용 설정이며 두 가지를 기억하십시오:

. **pod 가 재시작되면 저장된 데이터가 전부 사라집니다.** 시드한 secret 도 함께 사라지므로,
  세션 중 Vault UI 가 비어 있으면 다시 시드해야 합니다 (아래 트러블슈팅 참고).
. **root 토큰이 `root` 로 고정**되어 있습니다. 운영 환경에서는 절대 사용하지 마십시오.

참가자 가이드에도 이 내용이 NOTE 로 명시되어 있습니다.
====

== 사전 조건

* OpenShift 4.14+ 클러스터, `cluster-admin` 권한
* bastion 에 `oc`, `git`, `curl`
* Helm 3.6+ — 없으면 `install-vault.sh` 가 `~/.local/bin` 에 자동 설치합니다
* 외부 네트워크 접근 — `helm.releases.hashicorp.com` 과 `docker.io` 에서 차트/이미지를 받습니다

[NOTE]
====
폐쇄망이나 이미지 pull 이 제한된 환경이라면 `docker.io/hashicorp/*` 이미지를
미리 미러링해 두어야 합니다. 이 경우 `vault-values-openshift-lab.yaml` 의
`image.repository` 값을 미러 주소로 바꾸십시오.
====

== 설치

[source,bash]
----
cd ~/
git clone -b ocp-days-ops-1.0.0 https://github.com/justone0127/OpenShift_Day_Ops_Korean-demo.git
cd OpenShift_Day_Ops_Korean-demo/setup-scripts/security-track-scripts
./setup-security-track.sh vault
----

보안 트랙 전체(모듈 1/2/3)를 한 번에 준비하려면 `all` 을 쓰십시오.
**Vault 설치도 여기에 포함됩니다.** RHACS 와 ZTWIM 오퍼레이터는 이미 설치되어 있으므로
해당 단계는 워크로드 배포와 구성만 수행합니다.

[source,bash]
----
./setup-security-track.sh all
----

Vault 단계는 다음을 순서대로 검증하며, 하나라도 실패하면 그 자리에서 `[✗]` 로 기록합니다:

. `install-vault.sh` 존재 및 실행 성공
. Vault pod 가 **Ready** 될 때까지 대기 (최대 5분)
. `secret/narupay/payment-db` 를 기록한 뒤 **다시 읽어서** 확인

마지막 3번이 중요합니다. dev mode 특성상 "기록 성공"과 "실제로 읽힘"이 다를 수 있어,
읽기까지 확인해야 모듈 3 이 실제로 진행 가능한 상태입니다.

== 점검

[source,bash]
----
./verify-vault.sh
----

다음 6가지를 순서대로 확인하고, 실패 항목마다 해결 방법을 함께 출력합니다.

[cols="1,3",options="header"]
|===
| 점검 항목 | 확인 내용

| 0. 클러스터 접속
| `oc` 존재 여부와 로그인 상태

| 1. Vault 설치 상태
| `vault` namespace 와 server pod 가 Running/Ready 인지

| 2. Vault UI Route
| `route/vault` 존재 여부와 UI HTTP 응답 (참가자가 실제로 접속할 경로)

| 3. Vault 상태
| dev mode 자동 unseal 이 정상인지 (`sealed: false`)

| 4. 실습용 secret
| `secret/narupay/payment-db` 에 `username` / `password` 가 있는지

| 5. Kubernetes auth
| `kubernetes` auth method 활성화 여부

| 6. 비교 대상 애플리케이션
| `legacy-secret-app` deployment 와 `payment-db-creds` secret
|===

모두 통과하면 종료 코드 `0` 과 함께 Vault UI 주소를 출력합니다.
하나라도 실패하면 종료 코드 `1` 이므로 프로비저닝 파이프라인에서 게이트로 쓰기 좋습니다.

=== 자동 복구

[source,bash]
----
./verify-vault.sh --fix
----

현재 `--fix` 가 처리하는 것은 **secret 재시드**입니다.
dev mode 특성상 가장 자주 발생하는 문제이기 때문입니다.
설치 자체가 안 되어 있으면 `setup-security-track.sh vault` 를 다시 실행해야 합니다.

== 트러블슈팅

=== Vault UI 가 비어 있다 / secret 이 사라졌다

가장 흔한 상황입니다. dev mode Vault pod 가 재시작되면 데이터가 초기화됩니다.

[source,bash]
----
./verify-vault.sh --fix
----

pod 재시작 여부는 다음으로 확인할 수 있습니다:

[source,bash]
----
oc get pod -n vault -l app.kubernetes.io/name=vault,component=server \
  -o custom-columns=NAME:.metadata.name,RESTARTS:.status.containerStatuses[0].restartCount,AGE:.metadata.creationTimestamp
----

=== Route 는 있는데 UI 가 안 열린다

라우터에 전파되는 데 1~2분 걸릴 수 있습니다. 잠시 후 다시 확인하십시오.
계속 실패하면 Route 의 TLS 설정을 확인합니다 (dev 서버는 HTTP 로 뜨고 라우터에서 edge 종단합니다):

[source,bash]
----
oc get route vault -n vault -o jsonpath='{.spec.tls}{"\n"}'
----

=== 이미지 pull 실패 (ImagePullBackOff)

`docker.io` 접근이 막혀 있거나 rate limit 에 걸린 경우입니다.

[source,bash]
----
oc get events -n vault --sort-by=.lastTimestamp | tail -20
----

미러 레지스트리를 쓰신다면 `vault-values-openshift-lab.yaml` 의
`server.image.repository`, `injector.image.repository`, `injector.agentImage.repository`
세 곳을 모두 바꿔야 합니다.

=== Helm 설치 실패

`install-vault.sh` 는 Helm 이 없으면 `~/.local/bin/helm` 에 내려받습니다.
`PATH` 에 `~/.local/bin` 이 없으면 이후 단계에서 실패할 수 있습니다:

[source,bash]
----
export PATH="${HOME}/.local/bin:${PATH}"
helm version --short
----

=== Kubernetes auth 구성 실패

모듈 3 은 **개념 설명 중심**이라 이 항목이 실패해도 진행 자체는 가능합니다.
다만 구성 화면을 보여 주려면 다시 실행하십시오:

[source,bash]
----
../vault-config-scripts/configure-vault-lab.sh
----

== 정리

보안 트랙 전체를 정리할 때 Vault 도 함께 제거됩니다.
`cleanup` 은 SPIRE 플랫폼까지 지우고 namespace 삭제가 끝날 때까지 기다리므로,
곧바로 `all` 로 재구성할 수 있습니다.

[source,bash]
----
./setup-security-track.sh cleanup
----

SPIRE 플랫폼은 그대로 두고 워크로드만 다시 배포하려면:

[source,bash]
----
./setup-security-track.sh cleanup-lab
----

Vault 만 제거하려면:

[source,bash]
----
../vault-config-scripts/uninstall-vault.sh
----

== 모듈 3 에서 참가자가 실제로 하는 것

준비가 왜 필요한지 판단하실 때 참고하십시오. 실행 블록은 3개입니다.

[cols="1,3",options="header"]
|===
| 순서 | 내용

| 1
| `oc get secret payment-db-creds -n narupay ... \| base64 -d` — Secret 이 그냥 풀린다는 확인

| 2
| `oc exec ... env \| grep DB_` — **이 모듈의 하이라이트.**
  컨테이너 안에서는 RBAC 이 아무 의미가 없다는 지점

| 3
| `oc get route vault -n vault` 로 UI 주소 확인 후, 브라우저에서 secret 조회
|===

[TIP]
====
시간이 부족하면 **3번(Vault UI)만 진행자 시연으로 대체**해도 메시지는 전달됩니다.
1번과 2번은 `narupay` namespace 의 워크로드만 있으면 되므로 Vault 없이도 동작합니다.

즉 Vault 준비가 끝내 안 되면 모듈 3 을 통째로 빼는 대신
**개념 설명 + 실습 1·2번**으로 축소해 진행하는 선택지가 있습니다.
====
